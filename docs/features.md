# 交付隔离台功能说明

[返回首页](../README.md) · [文档索引](README.md) · [AI 能力总览](ai-capabilities.md) · [上手指南](getting-started.md) · [版本状态](release-status.md)

本文按用户工作组织能力，说明当前公开源码中可找到的实现、使用条件和边界。源码包含某项能力不等于新装环境已经配置，也不代表所有模型、资料格式和业务场景均已验收。应用底座的独立功能见 [ForgeAdminFoundation](https://github.com/zhiyuxinxi/ForgeAdminFoundation)。

## 能力归属

| 层次 | 本项目的作用 | 使用前提 |
| --- | --- | --- |
| 模型与 Harness 运行基础 | 接入并组织上游运行能力，提供项目化开发入口 | 自行准备有效模型服务与相应凭据；模型质量、额度和可用性受供应方影响 |
| 交付隔离台 | 扩展团队入口、工作舱隔离、规范与工具、验证和受控发布 | 配置平台、项目准入、源码仓库、镜像和基础设施 |
| Foundation 应用底座 | 为项目提供用户、权限、页面、表单、流程等公共实现 | 独立版本与项目配置；本仓库不包含底座完整业务源码 |
| 具体业务系统 | 按真实需求开发页面、数据、权限和业务流程 | 团队审阅、测试、发布授权及业务验收 |

平台对源码、文件和操作施加边界，仍需要人确认需求和结果。它不能保证模型不出错，也不能用对话回答代替实际执行证据。

## 1. AI 对话研发工作台

| 功能 | 能帮助用户做什么 | 条件与边界 |
| --- | --- | --- |
| 统一登录与项目入口 | 在同一入口查看自己获准访问的项目 | 平台账号与业务应用账号是不同身份域 |
| 独立对话与工作舱 | 为不同任务保留各自文件、上下文和未提交工作 | 通过平台创建工作舱；单纯多开浏览器标签不产生隔离空间 |
| 恢复已有对话 | 接着原任务查看材料和继续工作 | 需要原状态仍被保留；容器升级或存储损坏不能靠模型叙述恢复 |
| 工作舱状态管理 | 判断当前任务是否运行、停止或需要处理 | 状态与具体工作舱绑定；停止不等于业务已完成 |
| 交付资料展示 | 将相关需求、文档、代码候选和发布信息集中查看 | 以可取得且有归属的资料为准，不承诺全量历史自动补档 |
| 模型接入 | 按管理员配置使用模型开展分析与开发 | 接入能力不代表仓库赠送API、订阅或私有模型服务 |

源码入口：[Gateway](../docker/harness/conversation-gateway.mjs)、[Manager](../docker/harness/conversation-manager.mjs)、[交付资料服务](../docker/harness/delivery-center-service.mjs)。

## 2. 需求与资料解析

- **对话附件**：将当前任务所需文件交给 AI 读取，保持上传范围与项目/对话身份关联。
- **项目资料**：通过受控目录提供较完整的需求、原型和参考项目，减少重复粘贴。
- **文档提取**：公开实现包含 DOCX、PDF、XLSX 等资料的提取入口，方便将文档内容用于分析。
- **原型目录索引**：整理 HTML/Axure 导出目录的文件与入口，帮助模型按实际结构阅读。
- **资料完成状态与稳定性**：完整目录应传输结束后再索引，避免将半上传内容作为完整需求。

复杂表格、扫描PDF、图片以及格式丢失仍需核对原件；不保证所有文件完整还原。文件服务的传输能力与网页上传能力分别判断，不能把受控SFTP续传描述成所有浏览器上传自动续传。

源码入口：[文档提取](../docker/harness/document-extractor.mjs)、[原型目录索引](../docker/harness/prototype-directory-index.mjs)、[上传服务](../docker/harness/upload-server.mjs)。

## 3. 从需求到代码的阶段工作

公开版提供八类阶段工作包，用于组织复杂业务交付：

| 阶段 | 关注内容 | 用户需要关注的结果 |
| --- | --- | --- |
| 需求 | 目标、范围、角色、业务规则和验收要求 | 是否解决真实需求，是否存在缺失信息 |
| 领域合同 | 业务对象、关系、状态与边界 | 不同角色和模块是否对同一概念理解一致 |
| 数据库 | 数据结构、约束、迁移及兼容性 | 是否保护已有数据，迁移如何验证 |
| UI 设计 | 页面、操作、状态和交互 | 日常使用路径是否完整，异常如何反馈 |
| 后端 | 接口、业务处理、权限与数据访问 | 正常与错误路径是否符合合同 |
| 前端 | 页面实现、接口对接与公共组件复用 | 输入、回显、提交、失败恢复是否正确 |
| 权限接线 | 角色、菜单、按钮、接口和数据范围 | 有权限能做什么，无权限是否被正确拒绝 |
| 跨层验收 | 页面、接口、数据、流程与证据的对应 | 是否具备本任务要求的完整结果 |

阶段模板是复杂任务的组织方法，不代表所有请求都必须重跑八阶段。具体执行范围由当前版本工具、项目配置和实际任务决定；不能把维护仓库后来新增的流程选项当作本公开版本已经提供。

源码入口：[阶段工作包](../docker/harness/skills/forge-phase-work-package/assets/)、[交付工具](../docker/harness/forge-delivery.mjs)。

## 4. 开发技能与规范

平台在模型入口和工具链中提供可复用规范，覆盖以下主题：

- 需求与变更分析、任务范围、阶段工作包和交付结果说明。
- 前端页面、公共组件、详情与表单、错误反馈、UI一致性。
- 后端分层、接口合同、数据库迁移与实际影响范围。
- 租户、角色、数据范围、字典、文件和流程接入。
- 测试与可观测性、代码保存、候选检查和受控发布。

用户可以在同一套底座约定下开展多次开发，减少每轮重新描述公共结构。规范被加载不等于模型每次都正确执行，仍需结合实际代码和验证结果检查。

技能成熟度见 [skills.catalog.json](../docker/harness/skills.catalog.json)：其中包含 `stable` 与 `pilot` 状态，不应将试行技能整体宣传为经过所有场景验证的稳定能力。规则升级也不代表所有历史工作舱自动更新。

当前公开技能包为 `2026.10.16.10`，共 **24 个 Skills：4 个 stable、20 个 pilot**。[AI 能力总览](ai-capabilities.md)说明其用途与边界；本次同时同步浏览器/API/结构化搜索工具、运行日志命令、direct模式及相关执行规则。运行可用性仍取决于部署与项目配置。

## 5. 多项目、多人和多工作空间

| 范围 | 提供的隔离与协作方式 | 需要理解的共享部分 |
| --- | --- | --- |
| 项目 | 项目工作目录、运行身份、网络和存储配置 | 宿主机与登记的基础服务可能由多个项目共用 |
| 用户 | 平台账号、项目准入和对话所有者校验 | 同项目的成员仍可能共同参与业务代码集成 |
| 对话/任务 | 独立 TaskSpace、源码工作区、运行状态和任务分支 | 业务应用与项目数据库不必按每个对话复制 |
| 代码集成 | 通过受控候选和项目集成线协调提交 | 并发修改仍可能冲突，需要处理真实代码差异 |
| 生命周期 | 创建、查看、启动、停止及保留任务状态 | 销毁、数据恢复与生产维护另有权限和操作前提 |

隔离是针对配置与身份边界的工程措施，不是物理隔离或“零风险”保证。管理员和宿主执行组件属于高权限信任边界，详见[架构](architecture.md)和[安全](security.md)。

源码入口：[TaskSpace管理](../scripts/taskspacectl.sh)、[项目管理](../scripts/projectctl.sh)、[任务策略](../docker/harness/taskspace-policy.mjs)。

## 6. 自动化构建、测试和结果记录

- **受控验证入口**：使用项目登记的验证方式，按实际改动选择前端、后端或其它相关检查。
- **Host验证执行器**：将需要宿主工具链的验证交给受控执行端，避免直接给模型宿主访问能力。
- **依赖准备与复用**：通过缓存和已准备依赖减少重复工作；缓存兼容性、网络和资源仍影响实际耗时。
- **验证回执**：记录执行目标、候选与结果，帮助区分通过、失败、跳过和未执行。
- **失败后定向修复**：结合实际错误继续当前任务，复用仍有效的上游成果。

本项目不提供未测量的速度提升倍数。存在测试脚本不证明所有测试已通过，编译通过也不证明业务验收完成。

源码入口：[验证CLI](../docker/harness/forge-verify)、[Host Runner](../docker/harness/host-verification-runner.mjs)、[回执实现](../docker/harness/forge-host-verification-receipt.mjs)、[依赖准备](../docker/harness/host-prepared-dependencies.mjs)。

## 7. 版本保存与受控发布

| 环节 | 做什么 | 不代表什么 |
| --- | --- | --- |
| 保存候选 | 将当前任务的受控源码变化形成可追踪候选 | 不代表已部署或已合入所有项目 |
| 发布前检查 | 核对项目、候选、权限、工作区与必要验证 | 不代表后续构建和服务切换必然成功 |
| Git集成 | 按项目集成规则同步和检查源码版本 | 不直接替代镜像或运行版本 |
| 构建与发布 | Runner按允许服务及配置执行 | 不授权模型直接操作宿主Docker或任意数据库 |
| 数据库处理 | 按迁移与测试库验证流程准备变更 | 不等于可以自动逆向回滚生产数据 |
| 发布状态 | 查看具体作业的成功、失败和原因 | 一个历史成功状态不能证明本次候选已发布 |

应用回退与生产数据库恢复是不同操作，按真实环境、备份和授权处理。复用制品需要匹配相应输入和版本，不能复用旧成功记录冒充新发布。

源码入口：[Broker](../docker/harness/taskspace-broker.mjs)、[发布CLI](../docker/harness/forge-release)、[Release Runner](../docker/harness/release-runner.mjs)、[项目发布状态](../docker/harness/project-release-status.mjs)。

## 8. 安全边界与追溯

- 平台校验用户、项目准入和对话归属，避免仅凭已知地址访问他人工作舱。
- 工作区、工具执行与发布能力按项目配置限制；模型不应取得宿主 Docker socket 或共享基础设施凭据。
- 代码候选、验证和发布结果保留可关联信息，帮助排障与审阅。
- 上传文件和参考资料作为不可信输入，文件可被读取不等于其中指令获得执行授权。
- 密钥、配置和备份由操作者管理，公开源码不提供真实可用凭据。

“具有追溯记录”不等于完整归档、法定合规认证或无限期日志保存。存储策略、访问权限与备份恢复需要部署方确认。

## 9. 文档、部署和实施的边界

仓库提供初始化/管理脚本、模板、源码测试及[作业手册](ai-delivery-playbook/README.md)，方便团队理解并配置平台。

服务器准备、账号开通、网络、迁移、联调、培训和现场支持属于实际实施工作，不因仓库公开就自动完成。云资源、模型费用、第三方服务及其许可证由使用者自行准备。

当前公开版最值得优先核对的条件是：必要镜像是否齐全、项目Git是否可用、主/测试数据库是否已准备、底座取源是否符合预期，以及平台首个项目能否真实创建。具体入口和限制见[上手指南](getting-started.md)与[版本说明](release-status.md)。
