# 模板元数据与证据分级

## 每份正式任务单应说明什么

| 字段 | 含义 | 示例 |
|---|---|---|
| 模板编号 | 稳定身份，不随文件名轻易变化 | `FA-CRUD-01` |
| 面向角色 | 谁负责复制和验收 | 产品经理、实施、研发负责人 |
| 适用阶段 | 本次只解决哪个阶段 | 表设计、前端实现、发布 |
| 前置输入 | 缺少什么就不能可靠执行 | 已确认 PRD、字段表、权限矩阵 |
| 人工最少输入 | 普通使用者真正必须提供什么 | 原话、角色、结果、业务正反例 |
| AI 自动补全 | 应从项目/材料自行读取什么 | 基线、路径、源码、Skill、测试合同 |
| 技术复核 | 哪些内容不能由产品背书 | 表/接口、权限实现、迁移、发布证据 |
| 平台依赖 | 依赖哪些 Forge Admin 能力 | TenantEntity、AiCrudPage、字典 |
| Skill 依赖 | AI 必须加载的官方 Skill | `forge-codegen-crud` |
| 输出合同 | AI 必须交付的文件和证据 | migration、代码、测试结果 |
| 人工门禁 | 哪些决定必须由人确认 | 权限、状态、生产发布 |
| 停止条件 | 何时不允许继续猜测 | 合同冲突、主库授权缺失 |
| 用户触发表达 | 用户通常会怎样提出这个任务 | “继续做”“修复”“发版” |
| 失败特征 | 哪些现象说明模板或产品没有工作 | 越过阶段、重复建环境、无证据完成 |
| 反馈与复测 | 问题应落到哪里、怎样证明关闭 | 反馈卡、回归、负责人、复测日期 |

对话协作模板还应标记任务编号、当前项目/版本、动作级别和不能声称的事项。字段不要求每份旧模板立刻机械补齐；在模板因真实任务发生修改时逐步补全，避免没有证据的大批量改写。

“可复制”不等于“占位符必须填满”。任何模板若要求产品人员提供当前项目可自动读取的 Git、文件路径、接口、表、构建或部署信息，应在可用性评审中失败。模板必须允许一段自然语言或材料附件启动，并由 AI 先生成可确认草案。

## 证据等级

- **S1 固定源码验证**：已在当前固定 Forge Admin 提交中看到实现、测试或迁移；
- **S2 官方 Skill 验证**：来自当前固定提交内的官方 Skill 和引用文件；
- **S3 真实会话验证**：在本项目 Harness 会话中实际执行并留下测试、迁移或发布证据；
- **S4 项目决定**：由项目负责人明确确认，但未必是平台默认能力；
- **S5 工程建议**：可选建议，必须明确写成建议，不能冒充平台事实；
- **S0 未验证**：只能进入待确认区，不得直接用于生产任务。

## 冲突处理

当通用模板、官方 Skill、源码和业务需求不一致时，先停止实施，生成“合同差异表”，至少包含：冲突项、各来源、可能影响、推荐选择、需要谁决定。未经决定，不得选一个看起来顺手的实现继续写。

例如 Forge Admin 的通用控制器中同时存在 RESTful 和 POST-safe 两类接口；官方代码生成 Skill 明确要求生成型 CRUD 使用 `GET /page` 与 `POST /getById/add/edit/remove/removeBatch`。因此生成型 CRUD 以 Skill 的专用合同为准，不能套用通用 PUT/DELETE 示例。

## 外部材料使用边界

外部 ProCode 包和历史对话可以复用：多层目录、逻辑视图、模板 ID、依赖关系、黄金路径、成熟度标识。不得复用：平台字段、权限码、API 路由、组件能力、流程规则和任何未经 Forge Admin 当前版本验证的业务结论。
