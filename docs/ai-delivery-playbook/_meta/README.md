# 模板治理与证据入口

这个目录不面向一次业务提问，而是防止模板库长期演进后出现三种问题：模板来源不明、不同版本相互冲突、AI 把建议当成平台事实。

> 维护者专区：普通产品、业务和 UAT 使用者不需要阅读或填写本目录。它应在导航中保持次要位置，不能成为开始业务任务的前置步骤。

维护者在新增或修改模板前，应先阅读 [模板元数据与证据分级](模板元数据与证据分级.md)。业务人员不需要理解全部元数据，只需确认模板的“适用版本”“依赖 Skill”和“停止条件”。

Forge Admin 正式模板的编号、状态和证据汇总见 [正式模板清单](模板清单.md)，版本事实见 [平台版本与证据台账](平台版本与证据台账.md)。

## 当前权威顺序

1. 当前目标项目自己的 `AGENTS.md` 与明确需求；
2. 目标项目中 Forge Admin 官方 `.agents/skills/`；
3. 目标项目固定提交对应的源码、迁移和测试；
4. 本库中标为“源码验证”或“会话验证”的模板；
5. 通用工程建议；
6. 外部示例包和历史对话，只能参考结构，不能作为业务事实。

## 本轮基线

- Forge Admin：`v1.1.2`，固定提交 `6eb2881e6f6af85a5348acf3da63cef53a873b0e`；
- 官方 CRUD Skill：`.agents/skills/forge-codegen-crud/`；
- 官方流程 Skill：`.agents/skills/forge-business-flow-development/`；
- Harness 已验证模型：Kimi K3、DeepSeek-V4-Flash；
- 模型分工证据：服务器真实会话，而不是根据价格或宣传推测。

升级 Forge Admin、切换提交、替换组件或修改 Harness 权限后，必须重审相关模板，不能只改版本号。
