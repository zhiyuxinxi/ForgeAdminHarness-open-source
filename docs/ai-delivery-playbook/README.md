Policy marker: `PLAYBOOK_HUMAN_PREFILL_V1`.

这不是一本要求从头读完的手册，也不是让产品人员填写技术表格的模板合集。它是一组**人和 AI 共同完成的工作卡**：人说明业务，AI 读取项目、补出草案并执行获准工作，专业人员复核技术证据。

## 第一次使用，只做这一件事

把下面这段发给当前项目的 AI。能回答多少写多少，不知道的留空或写“不知道”；不要为了填满模板去猜 Git、接口、数据库、构建或部署信息。

## 可直接复制给 AI：帮我建立任务

```text
我想处理一件事，请先帮我把它整理成可执行任务，不要立即改代码或发布。

我想做/修复：
谁会使用：
现在的问题或做法：
我希望最后看到：
参考材料或截图：
这次明确不做：

我不知道的内容请不要让我猜。请你：
1. 先读取当前项目允许读取的规则、上下文、Git 状态和相关现有实现；
2. 把信息整理成“已确认 / 从项目查到 / 暂定 / 需要我决定”四部分；
3. 技术路径、文件位置、接口、表结构、测试命令和部署方式由你查证并提出建议，不作为产品填写项；
4. 只问最多 3 个会改变业务结果、范围、权限或验收的问题；
5. 推荐本手册中下一张最合适的工作卡，并说明接下来会不会改文件、测试或发布；
6. 在我确认任务草案前，不进入高影响动作。
```

AI 的第一份产物应是任务草案，而不是让你补一张更长的表。如果 AI 要求产品人员选择陌生技术方案或执行 Maven、pnpm、Docker、SQL、服务重启，使用 [产品人员 Harness 安全试用卡](04-协作与治理/03-产品到AI交付/06-产品人员Harness安全试用卡.md) 让它停止并转技术复核。

## 人和 AI 怎样共同填写

任务单中的 `{{...}}` 是信息提示，不是必须由人填完的表单。统一按以下责任处理：

| 信息 | 默认责任 | 例子 |
|---|---|---|
| 业务事实和业务决定 | 产品/业务人员提供或确认 | 谁使用、什么算成功、退回后怎样处理 |
| 项目中可以查到的事实 | AI 自行读取并注明来源 | 分支、提交、技术栈、相似页面、已有接口和表 |
| 技术设计与实现路径 | AI 提案，研发/实施复核 | 表结构、接口合同、组件复用、迁移和测试方式 |
| 测试与发布证据 | AI、测试、Runner 产生 | 测试输出、镜像摘要、迁移结果、浏览器证据 |
| 高影响授权与风险接受 | 有权限的人明确决定 | 主库迁移、正式发布、真实数据处理、回退 |

详细规则和例子见 [最少上下文与 AI 代填规则](00-开始使用/02-最少上下文包.md)。不知道可以直接写“不知道”。AI 可以提出带推荐的决定卡，不能把无法查证的内容静默补成事实。

## 这套库有三种文档，不要混着用

- **人用入口和工作卡**：用业务语言开始任务，产品、业务和测试可以直接使用；
- **AI/技术执行合同**：包含表、接口、权限、Skill、迁移和测试要求，主要由 AI 读取、技术人员复核，不要求产品填写；
- **维护者资料**：`_meta/`、平台证据、模型会话和推广路线图，只用于维护模板和平台，不是普通任务的前置阅读。

端到端需求优先从 [黄金交付配方](06-黄金交付配方/README.md) 开始。配方负责安排步骤；使用者不需要自己把多张技术任务单拼成一个超级 Prompt。

进入 Harness 实施后，使用 [八阶段 Markdown 工作包](07-阶段工作包/README.md) 每次只拿一张阶段卡。Controller 会把输入、结果、可观察过程、验证、交接和 Memory candidate 与机器 JSON/回执摘要一起封存，缺失或漂移时不允许阶段推进。

## 不同完成状态不能互相冒充

`需求已确认`、`代码已修改`、`测试已通过`、`产品 UAT 已通过`、`已经发布` 是五个不同状态。产品人员只保障业务定义和 UAT 结论，不需要验证代码、数据库和部署的内部正确性；这些必须由自动测试、技术复核和 Runner 证据负责。

模板不能自动授权以下动作：真实客户数据处理，认证/租户/安全策略修改，主库迁移，正式发布，外部消息发送，跨项目或宿主机操作。Forge/Harness 的最终边界以 [安全与多人协作](../security.md) 和 [目标架构](../architecture.md) 为准。
