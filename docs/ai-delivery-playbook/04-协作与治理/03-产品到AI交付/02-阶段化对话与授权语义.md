# 阶段化对话与授权语义

- 模板编号：`DIALOG-CONTROL-01`
- 面向角色：产品经理、业务负责人、实施人员、AI 交付主持人
- 状态：可用试点；语义已按本项目真实偏航校准

## 目标

让普通使用者不必掌握服务器和框架细节，也能看懂 AI 正在做什么、是否越过当前阶段、下一步是否需要人工决定。一个会话只维持一个当前目标；一个短句只继承已有范围，不自动增加权限。

使用者不需要填写完整技术合同。只需说明当前想补充、纠正还是新建任务；项目、基线、正在运行的动作和已有写入由 AI 自动回显。AI 无法确认时必须停下，不能把识别责任转给产品人员。

## 常用动词的默认含义

| 用户表达 | 默认允许 | 默认不允许 |
|---|---|---|
| 查看、分析、检查、评审 | 只读证据并给结论 | 修改文件、提交、测试写入、发布 |
| 设计、整理、生成方案 | 生成或更新约定的文档草案 | 修改业务代码、数据库和运行环境 |
| 实现、修复、改代码 | 在当前项目和当前阶段修改已批准范围 | 发布、安装基础设施、跨项目操作 |
| 测试、验证 | 运行约定测试和可回收测试数据 | 主库迁移、正式发布、用清理掩盖失败 |
| 继续 | 继续上一条仍有效的唯一任务 | 扩展范围、跳到下一阶段、继承已过期授权 |
| 发版、发布、上线 | 发布当前项目已批准且 clean 的提交，复用既有共享服务和白名单 Runner | 安装/创建 MySQL、Redis、数据库、账号或索取内部发布密钥 |
| 回退 | 先核对目标版本、影响和恢复证据，再按已批准运行手册执行 | 猜测回退点、删卷、清库或跨项目恢复 |
| 删除、清理、重建 | 只生成目标清单和影响说明，等待精确批准 | 模糊目标下执行不可逆动作 |
| 停止、不要打扰其他会话 | 停止当前相关动作并保留恢复点 | 停止、重启或清理其他人员的会话和容器 |

项目自己的明确决定和更严格安全规则优先于本表。涉及高风险动作时，必须使用对应专用任务单，不能只依赖一个动词。

## 产品友好决定卡

产品/业务使用者不需要替技术团队决定 RSA、API 建模、表结构、构建或部署方式。AI 先区分：

- 业务决定：由产品确认，但必须给推荐、影响和不决定的后果；
- 技术决定：按项目规范和源码证据处理，必要时由技术复核人确认；
- 平台阻塞：停止并生成升级卡，不要求产品人员执行服务器命令。

决定卡固定包含“发生了什么、业务影响、建议、需要产品确认、技术证据”。陌生技术术语第一次出现时解释业务含义，长日志放在后置证据区。

## 执行中新输入的语义

- “补充当前任务”：只能补充同一目标，不增加阶段或权限；
- “修正当前任务”：允许纠正目标内的事实或验收，但先说明对已有产物的影响；
- 无前缀的新要求若形成新交付物、进入下一阶段或触发发布，不静默合并，先停在安全边界并建议独立会话；
- “停止并替换当前任务”：先停止可停止动作，报告写入、运行中 job 和恢复点，再建立新合同；
- 新消息不授权重复提交正在运行的发布，也不授权重启 Harness、清理未知工作区或终止其他会话。

当前客户端尚未强制提供补充、排队和新会话三种发送模式，因此上述内容是受审临时协作规则，不是已经实现的输入队列能力。

## 会话开场握手

```text
请先确认当前任务，不要重复整份背景，也不要立即跨阶段执行。

项目/工作区：{{唯一标识}}
实施包：{{文件路径与版本}}
当前阶段：{{阶段}}
本轮目标：{{唯一交付物}}
本轮允许动作：{{只读 / 改文档 / 改代码 / 测试 / 已批准发布}}
本轮禁止事项：{{列表}}

先用不超过 8 行回复：项目、基线、当前阶段、允许动作、输出、验收、停止条件，以及最多 3 个会改变方案的阻塞问题。信息足够时直接开始，不要反复让我确认低风险细节。
```

## 执行中的回报协议

AI 只在以下节点更新：理解完成、发现会改变方案的冲突、完成可独立验收的阶段、需要高风险授权、发生失败并形成恢复点。每次更新包含“当前状态、完成证据、偏差/风险、下一动作”，不持续输出思维过程或长日志。

建议统一状态：

- `understood`：目标与边界已建立，尚未执行；
- `working`：只在批准阶段内执行；
- `blocked`：缺少会改变结果的决定、权限或外部条件；
- `ready_for_review`：交付物已产生，等待人工验收；
- `verified`：当前阶段证据通过，但尚未发布；
- `released`：批准版本已经发布并有运行证据；
- `rolled_back`：已恢复到明确版本并完成验证。

“代码已生成”“测试已通过”“已发布”不能互相替代。

## 偏航后的可复制纠偏

```text
当前对话发生偏航，请停止新增动作，不要重做全部工作。

当前任务：{{任务编号/实施包}}
观察到的偏差：{{AI 实际做了什么或准备做什么}}
正确边界：{{应该做什么}}
保留的有效产物：{{文件/提交/证据}}
本轮允许修复：{{精确范围}}
禁止事项：{{范围}}

请先输出：偏差影响、是否发生写入、可保留产物、最小恢复方案和验证方法。只有在当前授权明确覆盖修复时继续；否则停在可评审状态。不得删除不明文件、停止其他会话或用重建环境掩盖问题。
```

## 人工验收

从会话任意一个阶段更新中，应能看出当前项目、任务、动作级别、完成证据和下一审批点。若需要根据模型语气猜测“它到底有没有修改/测试/发布”，对话合同不合格。
