# 规模化推广与运营指标

- 模板编号：`DIALOG-SCALE-01`
- 面向角色：部门负责人、产品负责人、交付负责人、平台运营
- 状态：规划与试点模板；当前没有规模化成效证据

> 维护者资料：本页面向部门负责人和平台运营，不是普通产品人员开始任务的必读材料，也不应作为每个任务的填写表。

## 推广目标

推广目标不是增加 AI 对话数，而是让更多产品、业务和实施人员在明确边界内，更快地产生可验收交付物，同时不增加越权、返工、数据风险和运维负担。

## 推广前的最小标准包

每个项目至少具备：

- 唯一项目空间、Harness、Git 工作区、会话和运行资源登记；
- 项目上下文及“发版不含基础设施初始化”等固定边界；
- 已批准产品产物和当前阶段 AI 实施包；
- 角色化任务单、官方 Skill/平台能力入口和黄金交付配方；
- Git checkpoint、测试、受控发布、回退和浏览器 UAT 证据；
- 会话交接包、缺陷反馈卡及明确维护负责人。

缺少其中任何一项时，只做受指导试点，不宣称可大规模自助交付。

## 分阶段推广

| 阶段 | 使用方式 | 放大条件 |
|---|---|---|
| 影子观察 | AI 生成方案，人仍按原流程交付 | 能识别主要缺陷分类和证据缺口 |
| 全量复核 | AI 产出每一步，专业人员逐项批准 | 当前阶段任务通过率稳定，越权为零 |
| 辅助执行 | 普通人员驱动低风险设计/CRUD，技术人员审核发布 | 实施包、门禁和恢复流程经过代表性任务 |
| 有限规模 | 多项目、多人员使用，平台运营监测指标 | 项目隔离、身份、分支/任务归属和支持机制完成 |
| 规模运营 | 标准任务自助，异常进入统一反馈闭环 | 回归、审计、容量、备份、远端 Git 和事故响应成熟 |

## 指标体系

| 层级 | 推荐指标 | 说明 |
|---|---|---|
| 前置质量 | 实施包完整率、权威材料可定位率、阶段/权限声明率 | 判断任务是否在正确输入上开始 |
| 过程质量 | 首轮有效澄清率、阶段门禁通过率、纠偏轮数、升级/阻塞率 | 判断对话是否可控 |
| 交付结果 | 首次验收通过率、返工率、需求到可验证版本周期、发布成功率 | 衡量真实业务价值 |
| 信任与安全 | 无证据完成声明率、越权尝试率、秘密暴露、跨项目访问、人工回退率 | 任何高风险事件都应单独复盘 |
| 协作恢复 | 会话交接成功率、Git 恢复点覆盖率、冲突恢复时间 | 判断多人和长任务是否可持续 |
| 成本 | 单个验收任务 Token、构建时长、人工复核时间、支持工单量 | 防止只把成本从开发转移到支持人员 |

不要以消息数、登录人数、生成代码行数或 Token 消耗作为成功指标；这些只能说明使用发生过，不能说明交付正确。

## 运营责任

- 产品负责人维护任务入口、用户语言和验收标准；
- 平台负责人维护权限、版本、门禁、升级和运行稳定性；
- 交付负责人维护项目模板、评审与恢复边界；
- 每个缺陷有唯一负责人和复测日期；
- 每次模板或模型版本变化只做有限放量，保留上一版和回退方法。

## 当前不能声称

当前 `forge-base` 证明了代表性对话、代码、发布和浏览器验收链路，不证明高并发、多客户、个人身份审计、跨团队支持成本或无人值守交付已经成熟。推广范围必须随证据扩大，而不是随文档数量扩大。
