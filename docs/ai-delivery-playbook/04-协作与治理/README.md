# 协作与治理

本阶段保持人、AI 和不同专业角色之间的信息一致。它解决会议没有决定、对话无法续接、回答混乱、产品产物无法直接交给 AI 和上下文不断膨胀的问题。

## 子阶段

| 子目录 | 解决的问题 | 交付物 |
|---|---|---|
| `01-会议与交接` | 把口头讨论变成决定、行动和可恢复上下文 | 决策表、行动项、会话交接包 |
| `02-回答质量治理` | 重构混乱回答、核对事实并控制 Token | 精简结论、事实/假设表、压缩上下文 |
| `03-产品到AI交付` | 把已批准产品设计转成阶段实施包，规范授权语义、缺陷反馈和规模运营 | AI 实施包、对话合同、反馈卡、推广指标、产品路线图 |
| `多对话Git合并与数据库版本.md` | 解释独立分支如何进入唯一集成线、私有远端和串行数据库迁移 | 产品口径、合并规则、数据库版本边界 |
| [协作责任与信息边界](协作责任与信息边界.md) | 多人、多账号 Codex 的完整范围、前后端合同、消息送达和共同基线 | 可共享协作方法、最小交接内容、已验证与未验证边界 |

协作治理不能代替项目文档。稳定决定应回写 PRD、设计或运行证据；普通讨论不应自动升级为项目事实或长期 Memory。产品设计评审通过也不自动授权改代码、迁移或发布，每个阶段仍需独立实施包和动作边界。
