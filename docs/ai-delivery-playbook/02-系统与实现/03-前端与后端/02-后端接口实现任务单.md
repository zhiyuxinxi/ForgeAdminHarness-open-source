# 后端接口实现任务单

## 何时使用

业务规则、数据结构、接口合同和权限边界已明确，且当前会话获准修改代码时使用。

Forge Admin 生成型 CRUD 必须加载官方 `forge-codegen-crud` Skill；流程业务还要加载 `forge-business-flow-development`。专用 Skill 的接口、实体、Mapper 和验证合同优先于下方通用建议。

## 使用分工

产品人员确认业务动作、状态、错误结果、权限意图和数据含义。AI 自行读取基线、分层规范、相似模块、表/迁移、接口合同和测试模式；后端/DBA/安全人员复核事务、迁移、权限与兼容。下面是 AI/技术执行合同，不要求产品填写类名、表名、接口路径或测试命令。

## 可直接复制给 AI

```text
请在当前项目实现 {{后端功能/接口}}。

AI 实施包：{{已有就引用；没有时先由 AI 生成草案}}
任务编号/当前基线：{{由 AI 从当前项目确认}}
执行模式：{{仅设计 / 允许修改当前项目代码}}
PRD与验收：{{路径}}
领域/表结构/迁移：{{由 AI 从项目查找并注明来源}}
接口合同：{{由 AI 查证或先生成待评审草案}}
权限、租户与数据范围：{{说明}}
字典/流程规则：{{说明或“不涉及”}}
本次范围与非目标：{{列表}}

执行要求：
1. 先核对实施包中的项目、基线、当前阶段和允许动作，再读取项目规则、分层约定、错误码、审计、相似模块和测试模式；
2. 先报告影响模块、合同冲突、风险和实施计划；
3. 按现有风格隔离请求/响应模型、业务对象和持久化对象；
4. 完整处理校验、权限、数据范围、幂等、事务、并发、软删、分页和异常；
5. 导入、导出、批量和流程操作必须有独立边界与审计；
6. 新增表结构只能生成版本化迁移并先在测试库验证，不直接操作主库；
7. 编写正常、边界、无权限、非法状态、重复和失败回滚测试；
8. 执行相关测试、构建和静态检查；
9. 输出 API 清单、变更文件、迁移影响、测试证据、剩余风险和前端联调说明。

不得降低认证、租户隔离、安全或审计边界来换取通过。无证据不得宣称完成。
```

## 人工验收

产品确认业务结果和错误表达；研发审查事务、权限、迁移和兼容；测试验证越权、重复、非法状态与依赖失败。接口返回成功不代表数据和审计正确。

## 停止条件

需要真实数据修复、主库迁移、生产凭据或跨项目访问时，停止代码任务并请求单独授权与运行手册。
