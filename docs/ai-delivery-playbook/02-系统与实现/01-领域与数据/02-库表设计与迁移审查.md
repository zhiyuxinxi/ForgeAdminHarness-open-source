# 库表设计与迁移审查

## 何时使用

领域对象、查询场景和业务规则已明确，需要新增或修改库表时使用。它同时覆盖常见 CRUD、用户归属、审计和迁移，但不授权执行生产迁移。

若目标是 Forge Admin，先加载官方 `forge-codegen-crud` Skill，并同时使用 [对应 CRUD 黄金路径](../../05-Forge-Admin底座复用/03-业务模块黄金路径/README.md)。下述通用字段清单不能覆盖 `TenantEntity`、主键墓碑和 POST-safe 等平台专用契约。

## 这不是产品填写表

产品/业务人员只确认字段含义、归属、唯一规则、状态、历史保留和查询需求。AI 必须自行读取基类、现有表、迁移目录、数据量证据和数据库规范，并生成技术草案；研发/DBA 复核类型、索引、锁表、回填和恢复。产品人员不选择 SQL 类型、索引或 Flyway 版本。

## 默认字段检查表

AI 必须先检查项目的基类、命名和迁移规范，再决定是否复用：主键、业务编码、租户、组织/负责人、业务状态、创建人/时间、更新人/时间、软删除、乐观锁版本、排序和备注。用户标识通常作为权威引用；用户名只有在业务要求历史快照时才冗余保存。

## 可直接复制给 AI

```text
请为 {{业务范围}} 设计或审查库表，并生成“待评审”的版本化迁移方案。请自行读取项目规范、现有相似表、基类和迁移目录并引用路径；不得直接执行数据库变更。

输入：
- 领域对象与关系：{{路径/摘要}}
- 读写/查询/导入导出场景：{{列表}}
- 数据量、并发、保留和历史数据：{{已知信息}}
- 租户、组织、负责人和数据范围：{{规则}}
- 当前数据库与迁移工具：{{由 AI 从项目确认，不要求业务人员填写}}

每张表输出：表意图、字段名与业务含义、类型/长度、必填/默认、主外键、唯一约束、索引及对应查询、敏感级别、审计与生命周期。

逐项判断并说明：
1. 主键和业务编码；
2. tenant_id、org_id、owner_user_id 等归属字段；
3. created_by/created_at、updated_by/updated_at；
4. deleted/disabled 等删除或停用语义；
5. version 等并发控制；
6. status、sort_order、remark 是否确有业务需要；
7. 字典码、金额、时间、JSON、附件和用户名称快照的存储策略。

另输出：DDL/迁移草案、已有数据兼容与回填、锁表/性能风险、前向修复或回退策略、数据校验 SQL、受影响接口与测试。事实、建议、未知项分开。
```

## 人工验收

业务人员确认字段含义、归属、状态和历史保留；技术人员确认类型、约束、索引、迁移和性能。表中不得出现明文口令、Token 或无边界的“万能扩展 JSON”。

## 停止条件

生产数据分布、备份/恢复、迁移窗口或最小权限账号不明确时，只生成迁移草案与风险，不执行主库变更。
