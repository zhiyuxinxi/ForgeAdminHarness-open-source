# 数据字典设计

## 何时使用

字段取值有限、需要统一显示和校验，并可能由管理员配置时使用。高频变化、拥有独立属性和生命周期的数据应建业务表，不应硬塞进字典。

Forge Admin 实现使用 [字典与联动字典任务单](../../05-Forge-Admin底座复用/02-字典文件与数据交换/01-字典与联动字典任务单.md)，由 `sys_dict_type/sys_dict_data` 和平台组件形成前后端统一来源。

## 使用分工

业务人员确认每个值的业务含义、显示文案、是否允许停用以及历史影响。AI 自行查找现有字典、编码规范和全部使用位置，提出常量/字典/业务表建议；研发复核迁移与校验。产品不需要先发明 `dict_type` 或技术编码。

## 可直接复制给 AI

```text
请审查 {{字段/功能}} 的有限取值，并判断使用常量、项目数据字典还是独立业务表。

业务含义：{{说明}}
候选值与显示文案：{{列表}}
是否允许管理员新增/停用/排序：{{是/否/未知}}
是否影响流程、权限、计费或历史统计：{{说明}}
现有字典规范和相似字典：{{由 AI 从项目查找；找不到时报告缺口}}

输出：
1. 选择“常量/字典/业务表”的建议与理由；
2. 字典类型码、项编码、中文名称、说明、排序、启停、默认值；
3. 编码稳定性和重命名规则：编码不可随显示文案变化；
4. 数据库存储、后端校验、接口返回和前端显示的映射；
5. 未知值、已停用值、历史数据和版本兼容处理；
6. 初始化迁移或配置草案；
7. 测试与验收用例。

禁止只在前端写死；禁止直接删除仍被历史数据引用的字典项。
```

## 人工验收

业务人员确认编码含义、显示名称和停用影响；研发确认前后端共享同一来源。流程关键状态一般不能由普通管理员随意新增。

实机复盘补充：不能只看表单下拉框。必须同时检查列表、详情、打印、导入模板、导入、导出和后端非法值；任何位置出现 `private`、`hw`、`pending` 等内部 code，都说明字典契约没有闭环。后端允许值和状态机仍是业务权威，`sys_dict` 不能替代服务端校验，也不能让管理员任意新增流程关键状态。

## 停止条件

候选值会改变核心业务规则或历史统计含义时，先由产品负责人确认演进规则。
