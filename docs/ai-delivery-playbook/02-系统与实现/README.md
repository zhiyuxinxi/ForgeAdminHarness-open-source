# 系统与实现

本阶段把产品合同转成彼此一致的业务模型、数据结构、权限、字典、流程、页面和接口，并在获准后完成代码实现。业务人员不需要掌握框架细节，但必须能确认业务含义和验收结果。

本目录主要是 AI 与技术人员的执行合同，不是要求产品人员逐份填写的表格。产品可以从 [黄金交付配方](../06-黄金交付配方/README.md) 发起业务任务；协调 AI 根据业务形态选择本目录文件、读取项目事实并代填技术输入。

在 Forge Admin 项目中进入实现前，先使用 [Forge Admin 底座复用](../05-Forge-Admin底座复用/README.md) 做能力映射，并要求 AI 加载当前项目官方 Skill。通用任务单负责业务合同，Forge 专用任务单负责平台落地契约；两者缺一不可。

## 子阶段

| 子目录 | 主要问题 | 主要交付物 |
|---|---|---|
| `01-领域与数据` | 系统管理哪些业务对象，怎样持久化和演进 | 业务词汇、对象关系、表/字段/索引、迁移方案 |
| `02-权限字典与流程` | 谁能做什么，有限值怎样维护，状态怎样流转 | 权限矩阵、数据范围、字典、状态机或流程模型 |
| `03-前端与后端` | 用户怎样操作，系统怎样提供安全一致的能力 | 页面合同、前端代码、接口合同、后端代码、测试证据 |

## 核心原则

- 业务术语先于表名和类名，所有层使用同一语义；
- 设计前先读取项目现有规范和相似实现，不平地新造一套；
- 用户界面不能拥有后端未校验的业务规则；
- 权限既要控制按钮和接口，也要控制可访问的数据范围；
- 表结构变更必须通过版本化迁移，不直接手改生产库；
- AI 实现完成只代表“待验收”，不能自动代表可发布。
