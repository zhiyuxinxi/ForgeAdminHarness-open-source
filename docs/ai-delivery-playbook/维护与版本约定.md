# 维护与版本约定

> 公开版阅读提示：本文保留原有日期的维护背景与样本，其中内部部署和验收记录不代表当前公开版状态。未随公开包提供的材料只作历史来源说明，不是上手前置阅读。

这套作业体系会随真实项目演进，但不能把每次对话经验直接堆成新提示词。维护目标是减少重复、避免冲突，并让业务人员始终能找到唯一入口。

## 人用性优先于模板齐全

每次修改先回答：真实使用者是谁、他从什么原话或材料进入、最少需要提供什么、AI 能从项目自动补什么、哪些决定必须由人作、最后怎样知道可以结束。不能回答这些问题的文档，即使格式完整也不得标为“可用”。

普通使用者的首条消息应尽量控制在业务目标、角色、现状、期望、材料和非目标六类以内。Git、代码路径、接口、表、Skill、测试命令和发布证据默认由 AI/技术系统生成。新增占位符必须说明责任人；禁止把“AI 可以读取的信息”再次变成人工必填项。

## 新增文档的准入条件

只有同时满足以下条件才新增独立场景文档：

1. 对应一个可以独立验收的工作任务；
2. 输入、输出和人工判断点与现有文档明显不同；
3. 已在真实或代表性场景中发现重复需求；
4. 不依赖某一次会话的临时事实；
5. 能写出明确的停止条件和失败处理。

如果只是措辞优化，应修改原文；如果只是项目事实，应写进项目上下文、PRD 或交付证据，而不是写进通用模板。

真实项目经验先写入项目证据，再由 真实交付踩坑与跨项目复用经验（历史维护材料，未随公开包提供） 提炼“症状—根因—固定做法—最低验证”。能直接改善现有任务单的结论应回填原任务单；只有输入、输出和停止条件确实不同才新增模板。能够形成确定失败条件的经验进入质量门禁候选，经过跨项目验证后才进入版本化 Harness 能力包。

AI 对话问题统一使用 [对话缺陷反馈与模板演进](04-协作与治理/03-产品到AI交付/03-对话缺陷反馈与模板演进.md) 分类。业务事实回当前项目，表达和阶段合同问题回填既有任务单，产品可见性问题进入 Harness/门户产品路线图，可机器判断的问题进入门禁候选，客户端或运行能力缺陷进入版本化镜像、模板、幂等升级和回归。禁止用“再加一句提示词”覆盖所有根因。

## 文档状态

| 状态 | 含义 | 使用要求 |
|---|---|---|
| 草案 | 结构已形成，但未经过完整任务验证 | 只在试点中使用，记录问题 |
| 可用 | 已覆盖正常路径和主要边界 | 可供业务人员日常复制 |
| 已验证 | 已通过代表性黄金任务和反例验证 | 可纳入项目默认能力包 |
| 已废弃 | 被新文档替代或与当前系统冲突 | 保留迁移说明，不再导航 |

当前文档作为首版可用基线，仍需用真实客户项目验证，不宣称已经证明“任何非技术人员都能无人值守交付”。

Forge Admin 专用模板还应标记证据等级。平台字段、接口、组件和 Skill 合同必须来自固定源码或官方 Skill；真实会话只证明“这次实际做过”，不自动变成永久模型能力结论。具体规则见 [_meta/模板元数据与证据分级](_meta/模板元数据与证据分级.md)。

## 修改规则

- 场景文件名表达用户动作，不使用模型名或内部术语作为主分类；
- 通用规则只在 `00-开始使用` 维护，场景文档只保留当前任务必要约束；
- 项目专用规则必须标记作用域，不能伪装为行业通用规则；
- 对话反馈必须保留最短原始表达、预期/实际、证据、影响、根因层、永久落点和复测条件；
- 同一根因优先更新已有任务单；新增模板前检查是否只是入口、措辞或产品界面缺失；
- 外部示例包只允许复用结构思路，未经固定源码验证的 MD 内容不得进入正式模板；
- Forge Admin 版本或固定提交变化时，重审所有 `05-Forge-Admin底座复用` 模板；
- 官方 `.agents/skills` 变化时，Skill 合同优先于本库旧说明，并记录迁移差异；
- 修改任务边界、审批、数据迁移或发布行为时，必须同步项目架构和安全文档；
- 删除或重命名文件前，先更新 `场景总导航.md` 及所有相对链接。

## 每次版本复核

至少检查：是否有重复模板、普通用户是否要先理解目录结构、每个输入是否标明“人提供/AI读取/技术复核”、是否存在不必要占位符、是否存在相互冲突的字段或状态、导航/相对链接是否有效、是否要求 AI 提供无法获得的证据、是否把人工审批写成自动授权、是否存在会诱导粘贴密钥或真实敏感数据的文本、平台事实能否追溯到当前固定版本、对话问题是否被放到了正确层、推广指标是否衡量验收结果而不是消息量。

纯文档修改核对相对链接、版本与证据边界；涉及脚本、模板或平台行为时按实际变更选择直接相关验证，不因文档整理自动运行全仓测试。文档门户是构建时内容，Git推送不代表已发布网页；门户发布另按明确授权执行。平台文档、桌面台账和服务器运行台账分别是代码权威、人工快照和运行恢复边界，不得用其中一个冒充另外两个。
