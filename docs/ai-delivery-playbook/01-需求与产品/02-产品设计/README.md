# 产品设计

本目录把已确认的产品简报变成下游可执行的产品合同。PRD 说明“为什么、为谁、做什么和怎样验收”；用户故事补充角色视角、异常路径和细粒度验收。

## 使用选择

- 需要完整、可评审的需求基线：用 [编写可验收 PRD](01-编写可验收PRD.md)；
- 需要补全故事、异常、权限和边界：用 [用户故事与边界验收](02-用户故事与边界验收.md)。

## 阶段边界

PRD 可以记录对系统的必要约束，但不应提前锁死所有类名、表名和框架实现。涉及数据、接口、流程引擎的细化放到下一阶段，并保持业务术语一致。

通过标准是：业务、设计、研发、测试对本期目标和验收没有关键歧义，而不是文档篇幅足够长。
