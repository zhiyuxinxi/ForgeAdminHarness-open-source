# 需求与产品

本阶段把业务语言转成可被设计、研发和验收共同理解的产品合同。核心不是写长文档，而是消除目标、范围、规则和验收上的关键歧义。

产品人员可以从一句原话或一份附件开始，不需要按子目录顺序手工填写全部模板。AI 应先提取草案并推荐当前所需的一张工作卡；本目录中的表结构、技术可行性和现有系统事实由 AI/技术人员查证。

## 子阶段

| 子目录 | 解决的问题 | 主要交付物 |
|---|---|---|
| `01-需求沟通` | 到底为什么做、给谁做、什么值得解决 | 产品简报、澄清问题、事实/假设清单 |
| `02-产品设计` | 具体做什么、怎样工作、怎样算通过 | PRD、用户故事、业务规则、验收标准 |
| `03-方案与优先级` | 多个方案和需求怎样取舍 | 方案比较、优先级、验证计划、决策记录 |

## 阶段完成条件

- 目标用户、业务问题和成功指标明确；
- 本期范围与非目标得到负责人确认；
- 正常、异常、权限和数据边界有可验收描述；
- 重要假设有验证计划，重要决定有责任人；
- 下游可以据此设计数据、页面、接口和测试，不必重新猜业务意图。

没有满足这些条件时，AI 可以提出草案，但不能把需求状态标记为“已确认”。
