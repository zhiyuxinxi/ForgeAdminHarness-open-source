# 需求沟通

适用于需求尚处于想法、口头描述或多方意见不一致的阶段。本目录的目标是先确认问题和决定，不急于设计页面或写代码。

## 使用选择

- 只有一句想法：用 [模糊想法转产品简报](01-模糊想法转产品简报.md)；
- 已经有材料，但存在遗漏、冲突或争议：用 [需求澄清工作坊](02-需求澄清工作坊.md)。

## 本阶段输入与输出

输入可以是会议记录、用户反馈、现状流程、样例表格和负责人目标。输出必须至少包含：问题定义、目标用户、成功标准、范围、非目标、事实、假设和待决定项。

不要在本阶段要求 AI 直接生成表结构或代码。若技术限制会显著影响可行性，可记录为待验证约束，但不应让技术细节取代业务目标。
