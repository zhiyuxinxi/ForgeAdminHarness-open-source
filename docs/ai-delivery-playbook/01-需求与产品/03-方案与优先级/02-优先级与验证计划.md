# 优先级与验证计划

## 何时使用

需求数量超过本期能力，或高价值判断依赖未经验证的假设时使用。

## 使用分工

负责人提供版本目标、强制承诺和大致资源边界；AI 可从现有需求材料提取候选项、依赖和风险，并明确哪些工作量需要研发估算。产品不应为了让评分表完整而编造精确收益或工期。

## 最少输入

目标、候选需求、用户影响、合规/截止日期、依赖、粗略工作量、风险和可用资源。

## 可直接复制给 AI

```text
请为 {{版本/周期}} 建立可解释的优先级和验证计划，不默认所有需求都进入本期。

本期目标：{{目标}}
候选需求：{{列表或材料路径；AI 可从材料提取}}
硬性承诺或合规项：{{列表}}
可用资源与期限：{{约束}}
已知依赖和风险：{{知道就写；AI/技术从项目补查}}

请：
1. 先标记不可选项、强制项和信息不足项；
2. 使用“用户/业务价值、风险降低、紧迫性、学习价值、工作量、依赖”进行相对评估；
3. 给出本期、候选、暂缓、不做四组及理由；
4. 标记每项的关键假设和最小验证方式；
5. 输出版本目标、范围上限、顺序、负责人、验收信号；
6. 提供资源减少 30% 时的降级方案。

禁止伪造精确收益或工期；缺少证据时给区间和置信度。最终优先级由负责人确认。
```

## 人工验收

本期列表应能共同服务同一版本目标；暂缓和不做项必须有理由；强制项与高价值项混在一起时应清楚标注来源；验证计划必须比完整实现成本更低。

## 停止条件

资源、硬性承诺或核心依赖完全未知时，只输出待补信息和临时排序，不宣布正式路线图。
