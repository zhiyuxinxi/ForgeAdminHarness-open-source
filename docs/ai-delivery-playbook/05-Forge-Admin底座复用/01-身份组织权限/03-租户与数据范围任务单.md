# 租户与数据范围任务单

模板编号：`FA-IAM-03`  
平台依赖：`TenantEntity`、tenant Starter、datascope Starter、角色数据范围  
证据：Forge Admin v1.1.2 固定源码（S1）

## 已验证的平台范围类型

全部数据、本人、本组织、本组织及子组织、自定义组织、租户全部。具体代码值由当前版本枚举和配置确定，模板不要求业务人员记数字。

## 人与 AI 的分工

业务人员用“用户 A 应看到记录 1、不能看到记录 2”这类正反例确认可见范围。AI 自行读取 `TenantEntity`、datascope、Mapper 和现有角色配置，把例子映射为实现；技术/安全人员复核跨租户与后台任务。产品不选择拦截器、XML 或字段名。

## 可直接复制给 AI

```text
请为 {{业务模块}} 设计 Forge Admin 租户隔离和数据范围。先读取 TenantEntity、相似业务 Mapper XML、datascope 配置/枚举和当前角色数据范围实现。

数据拥有者：{{用业务语言描述；技术归属字段由 AI 提议}}
业务角色：{{列表}}
每个角色应该看到：{{本人/组织/下级/指定组织/租户全部等}}
跨组织协作与调岗规则：{{说明}}
后台任务、导入导出和流程回调：{{是否涉及}}

输出：
1. 表中 tenant_id、owner_user_id、org_id 等归属字段与索引；
2. 实体继承、Mapper XML 和数据范围配置的复用点；
3. 列表、详情、编辑、删除、导出、批量和后台任务的过滤/校验位置；
4. 角色默认范围和模块级覆盖规则；
5. 用户无组织、多组织切换、调岗后历史数据、超级管理员的处理；
6. 跨租户 ID、跨组织 ID、伪造请求头、缓存未刷新、异步任务上下文丢失的反向测试；
7. migration 与配置草案，以及上线后核验 SQL。

前端传入的 tenantId/orgId 不是授权依据。若当前项目已有 datascope 拦截配置，优先配置复用，不再手写重复过滤器。
```

## 工程门禁

- 业务实体优先继承 `TenantEntity`；
- 自定义查询仍要进入 Mapper XML 并接受租户/数据范围约束；
- 详情和写操作必须再次校验范围，不能只过滤列表；
- 导出通常比页面查询风险更高，应独立授权并验证相同数据范围；
- 流程回调和后台任务要显式恢复正确租户上下文。

## 停止条件

无法唯一确定数据归属字段，或“组织全部”和“租户全部”被业务混用时，不实施。先由业务负责人用具体示例确认哪些用户应看到哪几条记录。
