# 用户、组织与岗位复用任务单

模板编号：`FA-IAM-01`  
平台依赖：`SysUser`、`SysOrg`、`SysPost` 及用户—组织—岗位关系  
证据：Forge Admin v1.1.2 固定源码（S1）

## 何时使用

业务字段出现负责人、经办人、所属部门、协作部门、岗位或当前组织时使用。账号注册、认证方式、密码策略属于平台安全能力，不在此模板中重新设计。

## 人与 AI 的分工

业务人员只用具体人物例子说明“谁负责、属于哪个组织、调岗/离职后历史怎样显示”。AI 自行读取 `SysUser/SysOrg/SysPost`、相似业务表和选择组件，并提出 ID/快照映射；技术人员复核租户、数据范围和迁移。产品不填写实体、接口或索引。

## 可直接复制给 AI

```text
请把 {{业务功能}} 中的人和组织字段映射到 Forge Admin 已有用户/组织/岗位能力。先读取 AGENTS.md、相关实体/接口/页面和相似业务表，不要新建第二套用户或组织主数据。

业务角色与动作：{{例如项目经理负责、部门负责人审核}}
需要保存的人字段：{{用业务名称描述；技术字段由 AI 设计}}
需要保存的组织字段：{{用业务含义描述；技术字段由 AI 设计}}
是否需要岗位：{{说明}}
人员或组织变更后的历史显示要求：{{显示当前名称/保留当时快照}}

请输出：
1. 每个业务字段应保存 user_id、org_id、post_id、关系表还是历史名称快照；
2. 单选/多选、必填、可变更、变更生效时间和离职/停用后的处理；
3. 当前组织与用户多组织任职时的选择规则；
4. 前端选择器、后端存在性/状态校验和接口数据结构；
5. 数据范围会使用哪个归属字段，禁止只靠名称匹配；
6. 迁移、索引、审计和历史数据回填方案；
7. 正常、用户停用、组织停用、跨租户伪造 ID、多组织切换的测试。

明确列出复用的 Forge Admin 实体/接口与新增业务字段。事实与建议分开。
```

## 设计要点

- 权威引用保存 ID；只有合同、审批记录等需要还原历史文案时才冗余名称快照；
- “所属组织”与“当前处理组织”可能不同，必须由业务语义决定；
- 岗位表示任职，角色表示授权，两者不能互相代替；
- 用户可以绑定多个组织、角色、租户和岗位，不能假设一人一部门；
- 服务端必须校验引用对象属于当前租户且处于允许状态。

## 人工验收与停止条件

业务负责人确认人员变更、离职、跨部门协作和历史显示规则。若“负责人”到底是平台用户、外部联系人还是业务主体不明确，先停止表设计；三者的数据生命周期完全不同。
