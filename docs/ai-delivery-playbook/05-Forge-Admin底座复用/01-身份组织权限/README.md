# 身份、组织与权限

本目录把“谁能做什么、能看到哪些数据”拆成三层，避免把账号、岗位、角色和数据范围混成一个字段：

1. **身份与任职**：用户属于哪些租户、组织和岗位，当前以哪个组织工作；
2. **功能权限**：角色可以访问哪些菜单、按钮和 API 资源；
3. **数据范围**：同一个功能内，角色能看全部、本人、本组织、本组织及下级、自定义组织还是租户全部。

Forge Admin 当前源码已提供用户、组织、岗位、角色、资源、租户和相应关系表。业务表通常只保存稳定 ID 和必要历史快照，不应复制一套平台账号或组织树。

推荐顺序：先用 [用户组织岗位复用任务单](01-用户组织岗位复用任务单.md) 确认任职关系，再用 [角色资源与按钮权限任务单](02-角色资源与按钮权限任务单.md) 定义动作，最后用 [租户与数据范围任务单](03-租户与数据范围任务单.md) 约束数据。

人工验收必须至少包含：无角色、错误角色、跨组织 ID、跨租户 ID、停用用户、角色变更后缓存刷新这六类反向用例。
