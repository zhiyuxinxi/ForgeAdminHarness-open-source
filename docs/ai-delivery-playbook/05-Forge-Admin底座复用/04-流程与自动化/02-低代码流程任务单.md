# 低代码流程任务单

模板编号：`FA-FLOW-02`  
Skill 依赖：`forge-business-flow-development` 的 low-code 路由  
平台依赖：业务对象、表单资产、流程设计器、业务绑定、运行时动作

## 谁来使用

这是 AI/技术执行合同。产品人员只确认节点、参与人、条件、字段可见/可编辑和异常动作；AI 自行读取对象 code、表单资产、现有绑定与 Skill，流程实施人员复核并发布 BPMN。

## 可直接复制给 AI

```text
请按 Forge Admin 官方流程 Skill 的 low-code 模式，为 {{业务对象}} 配置真实 Flowable 流程。先读取 Skill 的 lowcode、BPMN、状态回调和验证清单；检查当前对象/表单/绑定源码与已有配置。

业务对象 code：{{由 AI 从当前项目确认或建议}}
表单资产：{{业务说明场景；路径和技术资产由 AI 查找}}
节点、参与人和分支：{{列表}}
节点字段权限：{{可见/只读/可编辑}}
业务状态映射：{{草案}}
通知与抄送：{{要求}}

执行要求：
1. 使用真实流程设计器和已发布 BPMN，不用模拟状态按钮；
2. 建立业务对象与流程定义绑定，START_FLOW 动作进入平台运行时；
3. 节点表单优先使用 BPMN 的 formKey/formUrl/formJson/formFieldPermissions；绑定和流程默认值只作回退；
4. 明确 businessKey、recordId、processInstanceId 和字符串 ID 传递；
5. 配置 TASK_CREATED/TASK_COMPLETED/COMPLETED/REJECTED/CANCELED 等回调对应业务状态；
6. 不覆盖已有设计器编辑且非空的 BPMN；
7. 验证发起→审批、驳回/退回→修改→再提交、撤回/取消、只读历史和状态修复；
8. 输出配置/迁移、发布步骤、流程版本、测试证据和人工操作路径。

如果低代码运行时无法表达某条核心业务规则，停止并提出转代码优先的差异，而不是在前端塞不可审计脚本。
```

## 验收

从业务门户真实发起，待办出现在正确人员，节点字段权限正确，完成/驳回/取消后业务状态一致，历史详情只读且轨迹完整。仅能在流程设计器看到图不算完成。
