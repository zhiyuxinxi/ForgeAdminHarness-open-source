# 流程模式选择

模板编号：`FA-FLOW-01`  
Skill 依赖：`forge-business-flow-development`  
输出：模式决定和流程边界，不直接部署 BPMN

## 谁来使用

业务人员只回答参与者、顺序、条件以及退回/驳回/撤回的业务语义。AI 读取当前流程能力和相似实现，比较状态机、低代码和代码优先；技术负责人确认模式。产品不选择 BPMN 实现、businessKey 或回调机制。

## 可直接复制给 AI

```text
请完整读取 Forge Admin 官方 forge-business-flow-development Skill，判断 {{业务过程}} 应使用普通状态机、低代码流程还是代码优先流程。

发起条件：{{说明}}
参与者与选择规则：{{角色/负责人/组织负责人等}}
节点与分支：{{已知流程}}
退回、驳回、撤回、转办、加签、抄送、超时：{{要求}}
表单字段在各节点的可见/可编辑要求：{{说明}}
外部系统、资金、库存、消息等副作用：{{说明}}
并发量、流程版本和历史追溯：{{业务量级/历史要求由人说，技术策略由 AI 补}}

请输出：
1. 三种模式的适配表和推荐结论；
2. 流程边界内/外的业务规则；
3. 业务对象编码、流程模型 key、businessKey 方案；
4. 业务状态与流程任务状态的映射草案；
5. 需要的表单、绑定、变量、回调、通知和权限；
6. 最难的三个失败路径和验证方式；
7. 仍需业务负责人决定的问题。

不要生成 BPMN 或代码，直到模式、参与者、退回/驳回/撤回语义被确认。
```

## 判断提示

只要出现多人待办、节点权限、流程轨迹、运行中版本、退回修改再提交，通常已经超出普通状态机。只要出现复杂事务、专用表、外部副作用和强回调测试，通常应倾向代码优先，而不是把所有逻辑藏进设计器表达式。
