# 流程回调与状态验收

模板编号：`FA-FLOW-04`  
用途：流程实现后的独立审查，不负责设计新流程

## 谁来使用

这是 AI、研发和测试的技术验收卡。产品人员只提供业务上正确/错误的状态例子，不负责查 BPMN、回调代码或日志；AI 应从当前项目和运行证据自动收集这些输入。

## 可直接复制给 AI

```text
请只审查 {{流程/业务对象}} 的“流程实例—任务—业务状态”一致性，不新增需求。

输入：BPMN/流程定义={{由 AI 从当前项目定位}}
业务表与状态逻辑={{由 AI 定位}}
回调实现={{由 AI 定位}}
测试和运行日志={{由 AI/测试收集；缺失则判为证据不足}}

逐项输出证据：
1. businessKey、recordId、processInstanceId 是否唯一且可追踪；
2. TASK_CREATED、TASK_COMPLETED、COMPLETED、REJECTED、CANCELED 各自改变什么；
3. 重复、乱序、延迟、缺失回调的处理；
4. 事务回滚后流程已前进或流程失败但业务已提交的补偿；
5. 当前活动节点与业务状态不一致时如何检测和修复；
6. 退回修改再提交、撤回、最终拒绝、取消、终止的完整路径；
7. 流程版本、历史表单只读和审计证据；
8. 可自动测试、需集成测试、需人工测试的矩阵。

最终只能给出 PASS、CONDITIONAL PASS 或 FAIL。每个 PASS 都必须引用测试或可复核运行证据；不得因为正常路径通过就忽略失败路径。
```

## 最低测试矩阵

- 正常发起并最终通过；
- 驳回/退回至修改并重新提交；
- 发起人撤回或管理员取消；
- 两个审批人并发操作；
- 相同回调重复两次；
- 回调失败后重试；
- 业务状态被人为改错后修复；
- 查看历史实例时表单只读、权限和轨迹正确。
