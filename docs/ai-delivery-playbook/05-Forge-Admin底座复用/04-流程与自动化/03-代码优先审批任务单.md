# 代码优先审批任务单

模板编号：`FA-FLOW-03`  
Skill 依赖：`forge-business-flow-development` 的 code-first 路由  
适合：采购、合同、资金、库存、复杂工单等强业务规则

## 谁来使用

这是 AI/研发执行合同。产品人员确认状态和动作的业务语义、参与者、字段权限与不可逆副作用；AI 自行读取对象 code、业务表、相似流程和 Skill，研发复核事务、回调、补偿与版本兼容。

## 可直接复制给 AI

```text
请按 Forge Admin 官方流程 Skill 的 code-first 模式实现 {{业务审批}}。完整读取 code-first、BPMN configuration、status/callbacks、SQL templates 和 validation checklist，再检查相似代码优先流程。

对象 code：{{由 AI 从当前项目确认或建议}}
业务表/字段：{{AI 从项目读取；产品只确认业务含义}}
业务状态：{{若无特殊要求，评审 DRAFT/IN_PROCESS/NEED_MODIFY/APPROVED/REJECTED/CANCELED}}
节点与参与者：{{列表}}
表单和字段权限：{{规则}}
副作用：{{库存/资金/外部 API/消息等}}

输出并实现：
1. businessKey 默认 {{objectCode}}:{{recordId}}，表保存 business_key/process_instance_id；
2. TenantEntity 业务实体、DTO/Query/VO、Mapper XML、Service/Impl、Controller；
3. 流程定义、BusinessCodeFormProvider、BPMN builder 和表单路由；
4. 提交、审批、驳回、退回修改、取消的合法状态前置条件；
5. TASK_CREATED/TASK_COMPLETED/COMPLETED/REJECTED/CANCELED 回调，全部幂等且可重放；
6. 业务事务与流程调用边界，外部副作用使用可补偿/可重试设计；
7. 运行中流程版本兼容，禁止覆盖非空设计器 BPMN；
8. migration、资源权限、测试和发布证据。

前端不得直接产生不可逆业务副作用。流程引擎完成不等于业务副作用一定成功，必须能检测、重试和人工修复。
```

## 关键验收

- 重复回调不会重复扣减、重复通知或倒退状态；
- 失败后能根据活动节点修复业务状态；
- 驳回、退回修改和最终拒绝的语义不同；
- 并发审批、重复提交、流程实例缺失和业务记录被删除均有明确结果；
- 旧流程实例继续按旧版本执行，新版本只影响新实例，除非有批准的迁移方案。
