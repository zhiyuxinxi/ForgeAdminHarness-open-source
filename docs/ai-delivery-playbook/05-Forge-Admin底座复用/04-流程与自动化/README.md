# 流程与自动化

本目录处理三类容易混淆的需求：

业务人员不需要先选模式，只需讲清参与者、条件、退回/驳回/撤回语义和不可逆结果。协调 AI 使用“流程模式选择”生成推荐，技术人员复核后再进入相应执行卡。

- **普通状态机**：少量确定状态，无待办、转办、加签、流程版本和完整审批轨迹；
- **低代码流程**：业务对象和表单可由平台运行时表达，审批规则主要在设计器中配置；
- **代码优先流程**：复杂领域规则、定制表单/接口、强事务和可测试回调，需要 Java 业务模块承载。

先用 [流程模式选择](01-流程模式选择.md)，选定后再使用 [低代码流程任务单](02-低代码流程任务单.md) 或 [代码优先审批任务单](03-代码优先审批任务单.md)。无论哪种 Flowable 模式，最后都要使用 [流程回调与状态验收](04-流程回调与状态验收.md)。

流程引擎负责过程、任务和轨迹，业务服务负责业务规则和最终业务状态。两者必须通过稳定 businessKey、processInstanceId 和幂等回调连接，不能互相替代。
