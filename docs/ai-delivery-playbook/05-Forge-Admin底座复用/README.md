# Forge Admin 底座复用

本目录解决一个关键问题：业务人员提出“做一个功能”后，AI 应先复用 Forge Admin 已有的用户、组织、权限、字典、文件、Excel、流程和页面组件，而不是重新造一套相似能力。

本目录主要供协调 AI 和技术人员读取。业务人员不需要先认识 Forge 类名、Skill 或平台表；只需描述业务对象、角色、动作、规则和验收，然后从 [黄金交付配方](../06-黄金交付配方/README.md) 开始。AI 负责选择这里的专项合同并代填项目事实。

## 使用顺序

1. 在 [平台能力地图](平台能力地图.md) 判断底座是否已有对应能力；
2. 用 [官方 Skills 调用与证据规则](官方Skills调用与证据规则.md) 区分项目源码 Skill 与 Harness 工作流 Skill，再从 [Harness 版本化 Skills 使用清单](Harness版本化Skills使用清单.md) 选择当前专用能力；
3. 选择一个能力任务单或业务模块黄金路径；
4. 只粘贴本次所需模板和当前需求，不发送整个目录；
5. AI 输出合同差异、实施文件和验证证据后，再进入发布阶段。

## 目录说明

- `01-身份组织权限/`：用户、组织、岗位、角色、菜单、按钮、租户和数据范围；
- `02-字典文件与数据交换/`：字典、区域、文件、图片、Excel 导入导出；
- `03-业务模块黄金路径/`：单表、主子表、左树右表，以及低代码/代码选择；
- `04-流程与自动化/`：普通状态机、低代码流程、代码优先审批和回调一致性；
- `05-模型协作/`：Kimi K3 与 DeepSeek V4 的本项目验证分工和交接包；
- `06-运营监控与集成/`：消息、任务、配置、日志、缓存、外部 API 与 AI 能力接入。
- `Harness版本化Skills使用清单.md`：任务合同、需求覆盖、字典、UI、Git、受控发布和发布后验收的选择入口。

## 不能从模板直接得出的结论

模板不会替业务负责人决定角色权限、审批条件、字段含义、历史数据处理或生产发布时间；也不证明某个已存在的底座功能在当前部署中已经启用。AI 必须同时核对目标项目固定版本、配置、迁移和实际运行环境。

## 当前适用基线

内容依据 Forge Admin `v1.1.2` 固定提交、该提交中的官方 CRUD/流程 Skills，以及服务器真实 Harness 会话整理。升级后先执行版本差异审查，再复用模板。
