# 通知、消息与公告任务单

模板编号：`FA-OPS-01`  
平台依赖：message 插件、通知公告、消息模板、阅读记录  
证据：Forge Admin v1.1.2 源码模块与页面（S1）

## 人与 AI 的分工

业务人员确认什么事件需要通知、谁应该收到、何时算重复骚扰、失败时怎样人工处理。AI 自行读取 message 插件、模板和相似实现，设计事务、幂等与重试；技术人员复核。产品不填写消息表、Bean 或发送代码。

## 可直接复制给 AI

```text
请为 {{业务事件}} 设计并接入 Forge Admin 现有消息/通知能力。先读取 message 插件、公告/模板/阅读记录相似实现和测试，不新建不可追踪的直接发送代码。

触发事件：{{发生什么}}
接收人规则：{{用户/角色/组织/流程参与者}}
渠道：{{站内信/公告/邮件/短信/其他}}
时效与去重：{{立即/汇总/最多一次/至少一次}}
模板变量与敏感字段：{{列表}}

输出：事件—接收人—渠道矩阵、模板及变量校验、发送时机、业务事务边界、幂等键、失败重试/死信/人工补发、已读与撤回规则、审计与监控、权限和测试。

不得在业务数据库事务尚未提交时产生不可撤销外部消息；不得把手机号、邮件、密钥或敏感业务数据写入普通日志。
```

## 验收

重复事件不产生重复骚扰；接收人变更和组织变更有明确规则；发送失败不回滚已完成业务也不悄悄丢失；无权限用户不能阅读他人通知；模板缺变量时失败可查。
