# 主子表黄金路径

模板编号：`FA-CRUD-02`  
Skill 依赖：`forge-codegen-crud` 的 `master-detail` 路由  
适合：订单与明细、合同与条款、巡检单与检查项等

## 谁来使用

业务人员只说明“哪部分是一张单、哪部分是多行明细、是否必须一起保存、汇总和状态规则”。是否采用主子表、如何事务保存和差异更新由 AI 提案、技术复核。下面不是要求产品填写 Java/数据库结构的表。

## 可直接复制给 AI

```text
请按 Forge Admin 官方 forge-codegen-crud Skill 的 master-detail 模式，实现 {{主单据}} 与 {{明细}}。不得把两个独立 CRUD 页面拼成“主子表”。

主表字段与唯一规则：{{业务字段和唯一含义；技术类型由 AI 补}}
子表字段、数量与排序规则：{{业务含义；技术结构由 AI 补}}
保存方式：{{整单提交/允许明细独立操作/未知}}
金额/数量汇总与舍入：{{规则}}
单据状态和可编辑条件：{{规则}}
权限、数据范围、导入导出：{{规则}}

输出并实现：
1. 主子表键、tenant_id、排序、唯一约束、级联/逻辑删除方案；
2. 新增和编辑整单的事务边界，子项新增/删除/重排的差异算法；
3. 服务端重新计算汇总，禁止信任前端总额；
4. DTO/VO 的 children 结构、校验错误定位到具体行；
5. Mapper XML 查询，避免逐行 N+1；
6. AiCrudPage childrenConfig 或当前版本相似主子表实现；
7. 状态锁定、并发修改、重复提交、部分失败和回滚；
8. migration、资源、Excel 多行映射与测试证据。

先报告“整单原子性”决定。如果业务允许子项独立审批或独立生命周期，请停止套用普通主子表，先重新划分领域对象。
```

## 关键验收

- 主表成功而子表失败时整单回滚；
- 编辑时删除的旧明细有明确逻辑删除或物理删除规则；
- 子表排序、重复行、空明细、最大行数和金额汇总准确；
- 两人同时编辑不会静默覆盖；
- 详情、导出和流程表单中的子项顺序一致。
