# 业务模块黄金路径

Forge Admin 官方 CRUD Skill 已验证三种主要形态：单表、主子表、左树右表。本目录把它们翻译成业务人员能选择的交付路径。

业务人员不必先作技术分类。只要描述“一条独立记录 / 一张单带多行 / 左侧分类筛右表”以及真实例子，协调 AI 应推荐模式、说明理由并读取相应合同；模式选择由技术人员复核。

| 业务形态 | 选择 |
|---|---|
| 一条记录独立增删改查，没有从表 | [单表 CRUD](01-单表CRUD黄金路径.md) |
| 单据头和多行明细必须一起保存 | [主子表](02-主子表黄金路径.md) |
| 左侧树用于筛选，右侧维护当前节点数据 | [左树右表](03-左树右表黄金路径.md) |
| 还不确定用可视化低代码还是生成代码 | [低代码或代码开发选择](04-低代码或代码开发选择.md) |

三个模式共享的顺序是：确认需求与字段 → 新增 Flyway migration → 后端 → 前端 → 菜单/按钮/API 资源 → 测试库 → 人工验收。不得先做漂亮页面，再补数据库和权限。

生成型 CRUD 的专用接口合同是 `GET /page`、`POST /getById`、`POST /add`、`POST /edit`、`POST /remove/{id}`、`POST /removeBatch`。前端 `AiCrudPage` 的 `apiConfig` 必须与此对应，不套用泛化 PUT/DELETE 示例。
