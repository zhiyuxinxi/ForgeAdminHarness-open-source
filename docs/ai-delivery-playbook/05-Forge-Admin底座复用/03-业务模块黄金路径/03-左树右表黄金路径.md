# 左树右表黄金路径

模板编号：`FA-CRUD-03`  
Skill 依赖：`forge-codegen-crud` 的 `left-tree-right-table` 路由  
适合：组织—人员、分类—商品、区域—设备等“树筛选列表”场景

## 谁来使用

业务人员只描述左侧按什么分组、点父节点是否包含下级、右侧维护什么，以及移动/删除分类时怎样处理。AI 判断复用组织/区域还是业务分类，技术人员复核树约束、性能和数据范围。

## 可直接复制给 AI

```text
请按 Forge Admin 官方 forge-codegen-crud Skill 的 left-tree-right-table 模式，实现 {{左侧树}} 筛选 {{右侧业务表}}。

树来源：{{用业务语言描述；由 AI 判断 SysOrg/SysRegion/业务分类表}}
树是否允许维护：{{只筛选/可新增编辑删除}}
右表与树节点关系：{{必属一个/可属多个/允许未分类}}
选择父节点是否包含下级：{{是/否/由开关决定}}
权限与数据范围：{{规则}}

输出并实现：
1. 判断复用 SysOrg/SysRegion 还是新建业务树，禁止复制平台组织树；
2. 树的 parentId/ancestors/sort/status 与循环引用校验；
3. 右表外键、索引和当前节点筛选合同；
4. 父节点是否包含后代的明确 SQL 与性能策略；
5. AiCrudPage 的 table/tree 配置和页面高度/滚动布局，左树筛选时不误开“添加下级”；
6. 节点删除/移动时已有业务数据的阻止、迁移或重新归类规则；
7. 数据范围与树可见范围的一致性；
8. 懒加载、空树、大树、无权限节点和跨租户节点测试。

若左树只是组织或区域筛选，直接复用平台树和稳定 ID；不要新建一张结构相同、数据却不同步的表。
```

## 关键验收

选择节点、选择父节点、切换节点、刷新、无权限节点、已停用节点和节点移动后的数据均应正确；右侧详情/编辑仍要校验记录属于可见树范围，不能只靠列表过滤。
