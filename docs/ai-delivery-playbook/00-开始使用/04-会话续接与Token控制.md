# 会话续接与 Token 控制

长对话最容易浪费 Token 的原因不是任务复杂，而是重复传递已失效的历史。换会话时只保留当前真相、可验证证据和下一步边界。

正常情况下用户只需说“为当前任务生成交接包”。AI 应从当前会话、工作区和证据中自动整理，不让用户重新填写已完成工作、提交或测试结果。

## 应保留与应丢弃

保留：目标、已确认决定、当前文件或版本、完成证据、未解决问题、禁止事项、下一步。丢弃：讨论过程、被否决方案的长解释、重复日志、已失效代码片段和寒暄。

## 可复制压缩指令

```text
请把当前会话整理成可供新 AI 会话直接继续的交接包。不要继续执行任务。

输出固定为：
1. 当前目标（1 段）；
2. 已确认事实与决定（每条注明来源）；
3. 已完成工作（文件/版本/证据）；
4. 未完成工作及原因；
5. 当前风险、冲突和不能声称的事项；
6. 下一步唯一任务、输入、输出和停止条件；
7. 必须读取的文件路径，最多 10 个；
8. 可忽略的旧讨论。

限制：不复制长日志或完整代码；只引用路径和关键结论。事实、假设、建议分开。控制在 {{建议 800～1500}} 字。
```

## Token 控制规则

- 优先给文件路径和行号，不重复粘贴文件全文；
- 工具输出只保留错误、结论和证据摘要；
- 同一事实只保留一份权威表述；
- 一个会话维持一个当前目标，阶段切换时生成交接包；
- “简短”不等于缺证据，应压缩叙述而不是删除验收信息。
