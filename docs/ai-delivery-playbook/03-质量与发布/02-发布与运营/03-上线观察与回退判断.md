# 上线观察与回退判断

## 何时使用

版本已发布，需要在观察窗口内判断继续运行、修复、降级或回退时使用。

## 使用分工

业务人员提供关键业务结果和用户反馈；AI/平台收集版本、指标、日志、健康和迁移边界；有权限的负责人决定继续、降级或回退。不要让产品人员从原始日志中猜根因，也不要让 AI 仅凭“没有告警”判断业务正常。

## 可直接复制给 AI

```text
请基于证据监测 {{版本}} 的上线状态并给出继续/暂停/回退建议。未经单独授权不要执行回退。

发布时间与版本：{{AI/发布记录自动确认}}
变更范围：{{列表}}
发布前基线：{{可用率、错误率、响应、关键业务量}}
观察指标与阈值：{{列表}}
日志/告警/健康/用户反馈：{{平台收集技术信号，业务人员补用户现象}}
数据库迁移与回退边界：{{AI/DBA/Runner 提供}}
观察窗口与责任人：{{信息}}

输出：
1. 当前信号及来源，区分正常波动和变更相关异常；
2. 关键业务主路径和数据完整性状态；
3. 阈值触发情况、影响用户/数据/服务；
4. 继续观察、热修、降级或回退的建议与理由；
5. 每个选项的风险、执行前提和验证步骤；
6. 当前不能确认的事项和下一次检查时间。

不得用日志安静推断业务正常；不得把相关性自动写成根因。
```

## 人工验收

至少核对一个系统指标、一个关键业务结果和一个数据一致性信号。决定回退时同时确认代码/镜像可回退与数据库是否只能前向修复。

## 停止条件

出现越权、敏感信息泄漏、数据损坏、持续不可用或错误扩散时，立即升级人工处置；不要等待 AI 完成长篇分析。
