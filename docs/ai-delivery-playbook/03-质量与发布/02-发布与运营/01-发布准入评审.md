# 发布准入评审

## 何时使用

测试和 UAT 基本完成，需要决定是否进入发布窗口时使用。本任务只给准入结论，不执行发布。

## 使用分工

产品/业务负责人只确认发布的业务范围、使用窗口、已知用户影响和是否接受剩余业务风险。版本、提交、镜像、测试、迁移、配置差异和回退证据由 AI、研发、测试和 Runner 自动汇总；缺失时结论为不准入或有条件准入，不要求产品补技术证据。

## 可直接复制给 AI

```text
请对 {{版本}} 做发布准入评审，只读审查，不执行构建、迁移或发布。

目标环境与项目：{{说明}}
版本/提交/镜像：{{由 AI/Runner 从批准版本确认}}
需求、变更和非目标：{{路径}}
测试/UAT/权限证据：{{AI 汇总；产品只提供 UAT 结论}}
数据库迁移与数据影响：{{AI/研发/DBA 提供}}
配置差异、依赖和资源影响：{{AI/平台提供}}
回退点、观察指标和发布窗口：{{技术给回退点；业务给窗口}}
已批准人与允许动作：{{说明}}

输出：
1. 准入清单及证据位置；
2. 变更、依赖、数据库、权限、安全、性能和兼容风险；
3. 发布步骤、责任人、验证点和停止条件；
4. 回退触发、回退步骤和不能自动恢复的数据边界；
5. “准入/有条件准入/不准入”结论；
6. 发布前仍需谁确认什么。

任何证据不足必须标为不足，不得用经验推断已通过。
```

## 人工验收

确认评审对象是唯一版本；发布窗口、影响用户、数据库变化和回退范围清晰；有条件准入的条件必须在执行前关闭，而不是发版后补。

## 停止条件

目标环境、版本或授权不唯一，或不可逆数据变化没有备份/恢复策略时，结论必须为不准入。
