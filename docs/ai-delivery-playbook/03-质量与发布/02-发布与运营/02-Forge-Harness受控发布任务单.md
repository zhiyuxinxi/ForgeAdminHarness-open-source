# Forge Harness 受控发布任务单

## 适用范围

仅适用于本交付平台中的项目专属 Harness。发布必须先读取 `forge-release contract` 并通过 `forge-release preflight`，再由项目白名单 Runner 执行；Harness 本身没有 Docker、项目运维目录或共享服务凭据。本文不授权跨项目、任意宿主机、秘密访问或基础设施创建。

如采用 Kimi/DeepSeek 接力，先用 [双模型接力包](../../05-Forge-Admin底座复用/05-模型协作/03-双模型接力包.md) 汇总已完成实现和证据；发布会话不得重新猜测业务需求，也不得把上游模型的“已完成”当作测试证据。

## 谁填写发布信息

批准人只需明确“发布哪个项目的哪个已验收版本、发布到哪里、业务窗口和允许范围”。Git 提交、迁移版本、镜像、Runner 契约和回退点由 AI/Runner 从当前项目核对并回显，批准人确认唯一性。无法核对时停止，不把技术识别工作转给产品人员，也不向其索取 Runner token。

## 可直接复制给 Harness AI

```text
请在当前项目、当前可见会话中发布 {{版本/需求}}。只允许操作 {{项目 slug}}，不得访问其他项目或输出任何凭据。

目标环境：{{测试/正式}}
任务编号与 AI 实施包：{{AI 从当前任务确认并回显}}
批准版本：{{用户可说“当前已验收版本”；AI 必须解析为唯一 Git 提交再确认}}
批准范围：{{服务/模块}}
需求与验收证据：{{AI 从实施包和证据索引汇总}}
Flyway 迁移：{{AI/Runner 从批准提交识别并核对}}
发布窗口与批准人：{{信息}}
上一稳定版本与回退点：{{Runner/平台提供，缺失则阻断}}

按门禁逐阶段执行，每阶段先报告结果，失败立即停止：
A. 核对项目、任务、实施包、工作区、分支、版本、发布能力和工作区 clean 状态；
B. 运行受影响后端/前端测试、静态检查和构建；
C. 在项目 `_test` 库执行迁移并验证版本、表结构和代表性数据；
D. 构建唯一版本镜像，记录标签和 digest；
E. 经门禁满足后执行主库迁移、定向 Compose 发布、健康/API/页面冒烟。

测试库门禁必须使用本次刚构建的精确候选 Admin 镜像，不能沿用 project.env 中的旧镜像。Maven/pnpm 依赖缓存只用于加速且必须可重建，不得共享业务 JAR、target 或 dist；缓存命中不等于测试通过。长发布应使用同一 jobId 报告阶段和有界日志，禁止因页面暂时没有输出就重复发布。

最终报告必须包含：实际命令和退出状态摘要、测试计数、迁移前后版本、镜像标签/digest、发布服务、健康/冒烟结果、Git 提交、未执行项、风险、回退点和当前运行状态。

禁止：绑定 0.0.0.0、修改平台安全策略、输出 Secret、跨项目操作、删除卷、无审批批量数据变更、用重建掩盖迁移失败；禁止安装/启动 MySQL、MariaDB、PostgreSQL、Redis、MongoDB、Elasticsearch，禁止创建数据库/账号/授权或执行服务器级 SQL。共享服务不可达或数据库不存在时立即停止并报告给项目初始化人员/DBA。没有证据不得声称完成。
```

## 人工验收

逐项核对 A–E，而不是只看最后一句。确认使用项目主库与 `_test` 库、候选测试镜像与发布 digest 一致、版本与批准一致、只重建目标服务、没有创建基础设施、冒烟覆盖真实入口、回退点仍存在。冒烟后继续执行登录和代表性业务 UAT，HTTP 200 不能替代功能验收。

## 停止条件

项目/版本不唯一、工作区含未知变更、测试或测试库迁移失败、主库影响超出批准范围、镜像不可追溯、回退点缺失时立即停止并报告。不可逆销毁永远需要独立运行手册和明确批准。
