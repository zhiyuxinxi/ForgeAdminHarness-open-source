# 阶段准入与证据门禁

## 测试完成门禁

- 范围内需求可追溯到测试用例；
- 正常、边界、异常、越权、重复、并发和回滚场景已覆盖；
- 数据迁移、字典、流程、导入导出有专项验证；
- 失败和跳过项有责任人、影响和处置；
- 测试数据已脱敏且有清理/保留说明。

## 发布准入门禁

| 项目 | 必须有的证据 |
|---|---|
| 版本 | Git 提交/标签、镜像标签或摘要、变更清单 |
| 质量 | 测试、构建、静态检查和 UAT 结果 |
| 数据 | 迁移版本、测试库结果、主库影响与恢复策略 |
| 权限 | 正反角色、数据范围和敏感动作验证 |
| 运行 | 配置差异、资源影响、健康检查和监控项 |
| 回退 | 上一稳定版本、触发条件、责任人和可恢复边界 |
| 授权 | 环境、时间窗、目标项目和允许动作的明确批准 |

## 状态语言

- `planned`：已计划，尚未执行；
- `executed`：命令或操作已执行，结果待核对；
- `verified`：结果和副作用已复核；
- `blocked`：存在阻断项；
- `rolled-back`：已执行回退并复核当前状态。

报告必须使用准确状态，不能把 `executed` 自动写成 `verified`。
