# 质量与发布

本阶段把“AI 说做完了”转换成可复核证据，并在明确授权、可回退的前提下发布。测试、验收、发布和上线观察是四个不同状态，不能互相替代。

产品人员负责业务 UAT 和业务风险决定，不负责用 SQL、代码或构建日志证明技术正确。AI、研发、测试和 Runner 应主动收集技术证据，用业务摘要解释给产品；任何证据缺口按“未执行/证据不足”处理。

## 子阶段

| 子目录 | 目的 | 主要产物 |
|---|---|---|
| `01-测试与验收` | 从需求和风险生成测试，并审查真实结果 | 测试矩阵、UAT 记录、证据索引、缺陷台账 |
| `02-发布与运营` | 判断是否准入、受控执行、观察和回退 | 发布单、迁移/镜像证据、冒烟结果、观察与回退决定 |

## 原则

- 通过项必须有对应证据；未执行、跳过、失败不能写成通过；
- 接口返回成功不等于权限、事务、数据副作用和页面正确；
- 数据库迁移先测试库后主库，发布必须有唯一版本和回退点；
- 发版权限只在当前批准范围内生效，不因业务人员使用模板而扩大；
- 高风险失败优先停止或回退，不让 AI 通过连续盲重试扩大影响。
