# 按场景找入口

Policy marker: `PLAYBOOK_ROLE_ROUTING_V1`.

先看“我现在遇到什么”，不要先研究目录结构。普通产品/业务人员通常只需要前两张表；技术任务索引是给 AI 和专业人员继续下钻的。

## 产品/业务人员最常用的 8 个入口

| 我现在遇到什么 | 打开哪张卡 | 我只需要准备 |
|---|---|---|
| 只有一句想法、抱怨或改进建议 | [模糊想法转产品简报](01-需求与产品/01-需求沟通/01-模糊想法转产品简报.md) | 原话、谁受影响、希望怎样变 |
| 有附件、截图或 PRD，想让 AI 接手 | [产品设计转 AI 实施包](04-协作与治理/03-产品到AI交付/01-产品设计转AI实施包.md) | 材料位置、本轮目标、不做什么、怎样验收 |
| 有 Axure/HTML 多层目录，想完整上传并复刻 | [上传完整原型文件夹并让 AI 复刻](00-开始使用/05-上传原型文件夹并让AI复刻.md) | 原型文件夹、目标项目、本轮要复刻的页面 |
| 不会填任务单，或看不懂技术名词 | [最少上下文与 AI 代填规则](00-开始使用/02-最少上下文包.md) | 你的原始描述；其余让 AI 先查 |
| AI 正在做事，我要补充、纠正或换任务 | [阶段化对话与授权语义](04-协作与治理/03-产品到AI交付/02-阶段化对话与授权语义.md) | 说明“补充当前任务 / 修正当前任务 / 新任务” |
| AI 说已完成，我要看功能是否可用 | [UAT 与证据审查](03-质量与发布/01-测试与验收/02-UAT与证据审查.md) | 真实角色、入口、操作、期望和实际 |
| AI 多次修改但页面没变化，或要求我跑服务器命令 | [产品人员 Harness 安全试用卡](04-协作与治理/03-产品到AI交付/06-产品人员Harness安全试用卡.md) | 页面、时间、截图和会话引用 |
| 对话太长、要换人或换会话 | [AI 会话交接包](04-协作与治理/01-会议与交接/02-AI会话交接包.md) | 当前目标；AI 自己整理其余证据 |

## 按交付阶段选择

| 当前阶段 | 工作卡 | 人负责确认 | AI/专业人员负责 |
|---|---|---|---|
| 想法和澄清 | [需求沟通](01-需求与产品/01-需求沟通/README.md) | 问题、用户、目标、范围 | 整理材料、发现冲突、生成草案 |
| PRD 和验收 | [产品设计](01-需求与产品/02-产品设计/README.md) | 业务规则、异常、权限意图、验收 | 结构化 PRD、追踪缺口 |
| 方案和优先级 | [方案与优先级](01-需求与产品/03-方案与优先级/README.md) | 取舍、风险接受、版本目标 | 对比证据、成本和验证方案 |
| 数据、权限、流程设计 | [系统与实现](02-系统与实现/README.md) | 字段含义、谁能做什么、流程语义 | 从项目读取技术合同并设计实现 |
| Forge 功能实现 | [黄金交付配方](06-黄金交付配方/README.md) | 当前业务形态和验收 | 自动选择底座能力、Skill 和技术任务单 |
| 测试和产品验收 | [测试与验收](03-质量与发布/01-测试与验收/README.md) | 业务是否可用 | 自动测试、权限/数据/代码证据 |
| 发布和观察 | [发布与运营](03-质量与发布/02-发布与运营/README.md) | 窗口、业务风险、UAT | Runner 门禁、迁移、镜像、冒烟和回退证据 |

## 常见业务形态：让 AI 选配方

你不需要判断单表、主子表、Mapper、Flyway 或 Flowable。只描述业务形态，AI 应推荐配方并说明理由。

| 你看到的业务形态 | 推荐配方 |
|---|---|
| 资料或台账的查询、新增、修改、删除 | [普通 CRUD 功能](06-黄金交付配方/01-普通CRUD功能配方.md) |
| 一张单据带多行明细 | [普通 CRUD 功能](06-黄金交付配方/01-普通CRUD功能配方.md)，由 AI 选择主子表 |
| 有提交、审批、退回、撤回和待办 | [带审批业务](06-黄金交付配方/02-带审批业务配方.md) |
| 不同部门或角色看不同数据、做不同动作 | [组织权限业务](06-黄金交付配方/03-组织权限业务配方.md) |
| 有 Excel 模板、批量导入或导出 | [导入导出业务](06-黄金交付配方/04-导入导出业务配方.md) |
