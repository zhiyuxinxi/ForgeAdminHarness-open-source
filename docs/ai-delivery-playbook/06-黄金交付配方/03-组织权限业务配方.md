# 组织权限业务配方

Policy markers: `GOLDEN_RECIPE_START_CARD_V1`, `GOLDEN_RECIPE_HUMAN_DECISION_V1`.

适用于不同租户、部门、区域、负责人或角色看到不同数据、执行不同动作。最有效的输入不是“按部门控制”，而是几个具体用户和记录的正反例。

## 可直接复制给 AI：开始权限业务

```text
请按“组织权限业务配方”帮我建立权限任务。先用业务例子整理矩阵，不立即改权限配置。

业务功能：{{功能}}
用户/角色例子：{{例如经办人、部门经理、审计员}}
应该看到：{{每个角色能看到哪些具体记录}}
不应该看到：{{至少一个反例}}
可以执行：{{查询/新增/编辑/删除/审核/导出等}}
调岗、离职或跨部门协作：{{知道就写}}
产品验收：{{用哪些角色和数据验证}}

请自行读取 Forge Admin 的用户、组织、岗位、角色、资源、租户和 datascope 实现。不要让我填写权限码、字段名、拦截器或 SQL。
先输出角色—动作矩阵、角色—数据范围矩阵、事实/假设/待决定、最多 3 个关键问题、技术映射建议和反向测试计划。
```

## 人必须确认的内容

- 每个真实角色能看哪些、不能看哪些；
- 能新增/编辑/删除/审核/导出哪些记录；
- 调岗、离职、多人任职和历史记录怎样处理；
- 至少一个跨组织或跨租户请求必须被拒绝的例子。

## AI/技术负责的内容

AI 选择稳定归属字段、平台用户/组织引用、资源/按钮/API、租户和数据范围实现；安全/技术人员复核列表、详情、写操作、批量、导出和后台任务是否使用同一边界。

## 完成定义

至少用两个组织、两个角色和一个越权 ID 完成黑盒验证。菜单隐藏不能代替 API 拒绝，列表过滤不能代替详情和写操作鉴权。
