# 黄金交付配方

Policy marker: `PLAYBOOK_GOLDEN_RECIPE_ENTRY_V1`.

配方是普通使用者推进完整需求的首选入口。你只需选最接近的业务形态并复制一张启动卡；协调 AI 负责选择 PRD、数据、权限、Forge Skill、实现、测试等内部步骤，不要求你手工拼接多份任务单。

| 你的业务看起来像 | 选择配方 | 你要做的决定 |
|---|---|---|
| 台账、配置、资料维护、一个对象的增删改查 | [普通 CRUD 功能](01-普通CRUD功能配方.md) | 字段含义、业务动作、角色和验收 |
| 一张单据带多行明细 | [普通 CRUD 功能](01-普通CRUD功能配方.md) | 哪些必须整单保存、汇总和状态规则 |
| 提交、审批、待办、退回、驳回或撤回 | [带审批业务](02-带审批业务配方.md) | 参与者、条件和异常动作语义 |
| 不同组织/角色看到不同记录或执行不同动作 | [组织权限业务](03-组织权限业务配方.md) | 具体用户正反例 |
| Excel 模板、批量导入或导出 | [导入导出业务](04-导入导出业务配方.md) | 列含义、匹配/冲突、权限和失败处理 |

一个需求可以同时命中多个配方。先选主配方，协调 AI 在实施包中加入必要专项，不要让使用者复制四张卡。

## 配方运行方式

1. 人提供业务原话、材料、本轮结果和产品验收；
2. AI 自动读取项目、确认基线、推荐配方和当前阶段；
3. AI 每次只执行一个阶段，并生成下一阶段所需输入；
4. 产品确认业务，技术人员复核技术，测试和 Runner 产生证据；
5. 发布始终是独立授权，不因前面步骤完成而自动发生。

技术任务单是配方的内部执行合同。普通使用者不需要按目录顺序阅读，也不需要填写 Git、类、表、接口、Skill、测试命令或部署字段。
