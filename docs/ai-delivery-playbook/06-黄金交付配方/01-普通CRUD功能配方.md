# 普通 CRUD 功能配方

Policy markers: `GOLDEN_RECIPE_START_CARD_V1`, `GOLDEN_RECIPE_HUMAN_DECISION_V1`.

适用于台账、配置、资料维护，以及一个主单带多行明细但没有复杂审批的功能。你不需要先判断单表、主子表或左树右表，AI 会从需求和现有项目中推荐。

## 可直接复制给 AI：开始一个 CRUD 功能

```text
请按“普通 CRUD 功能配方”帮我建立任务。先生成草案和当前阶段计划，不立即发布。

我想维护的业务资料：{{例如环保服务商、合同、设备；一句话也可以}}
谁会使用：{{角色}}
需要做的动作：{{查询/新增/编辑/详情/删除/状态变化；知道多少写多少}}
我最关心的规则：{{必填、唯一、状态、计算、不能修改等}}
参考材料：{{PRD、Excel、截图或现有页面}}
产品验收：{{用户最终能完成什么}}
本次不做：{{可留空}}

请自行读取当前项目、基线、现有相似模块、Forge Admin 能力和相关 Skill。不要让我填写类名、表名、API、组件、migration、测试或发布信息。

第一轮输出：
1. 业务任务草案与最多 3 个关键业务问题；
2. 推荐单表/主子表/左树右表或其他模式及业务解释；
3. 复用能力与新增内容；
4. 分阶段计划、每阶段的人工/AI责任和停止条件；
5. 本轮允许动作建议；未经我确认不进入发布。
```

## 人必须确认的内容

- 每个字段在业务中表示什么，哪些必填/唯一；
- 谁能查询、新增、修改、删除、导入、导出或改变状态；
- 哪些状态下允许编辑或删除；
- 一个成功例子和一个必须拒绝的例子；
- 产品 UAT 要看到什么。

字段技术类型、租户/审计基类、接口、表、索引、组件、迁移和测试由 AI/技术人员负责。

## AI 内部阶段链

1. 从材料生成产品/字段/权限草案，补齐异常与验收；
2. 读取平台能力地图和官方 Skill，选择实现模式；
3. 形成数据、接口、页面、字典和权限合同；
4. 在获准范围实现 migration → 后端 → 前端 → 资源；
5. 运行自动测试和构建，生成产品 UAT 路径；
6. 产品 UAT 与技术验收分别通过；
7. 获独立授权后才进入受控发布。

协调 AI 可以引用专项任务单，但不得要求普通使用者手工组合它们。

## 完成定义

“页面能打开”不是完成。范围内动作、字典、权限正反例、数据一致性、宽/窄屏弹窗、自动测试和真实产品 UAT都要有状态。未获发布授权时，明确停在发布门前。
