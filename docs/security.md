# 安全边界与部署责任

本项目提供受控开发交付机制，公开源码不构成安全认证或生产就绪证明。部署者需根据自己的网络、数据与人员权限配置环境，并验证实际消费者。

## 网络与身份

示例配置默认绑定 `127.0.0.1`。远程访问需要明确可信网络、入口和权限；不能直接改为公网监听就视为部署完成。`HARNESS_PRIVILEGED_API_MODE=trusted-host` 面向经过审核的可信主机访问场景，不是通用公网托管配置。

Gateway 校验账号、项目成员关系和对话归属。管理员受限查阅不等于可以接管所有人的会话。入口及动态工作舱请求需要正确的 Host、Origin 和代理配置；TLS、Cookie、防火墙和反向代理需作为一条真实访问路径验证。

## 运行与数据边界

Harness 不获得宿主 Docker socket、任意宿主目录或数据库管理权限，通过受控接口请求验证和发布。Manager、Runner 等具备特权职责的控制组件仍需保护镜像、挂载、身份、API 和审计。

项目隔离目录、Compose 资源、Git 与资料；对话隔离可变开发状态。共享 MySQL/Redis 实例仍需独立授权；Redis 逻辑库编号不是强安全隔离。

| 内容 | 管理原则 |
| --- | --- |
| 模型 API Key | 服务器 Secret 提供，不放入 Git、截图或聊天 |
| 数据库与缓存凭据 | 受限配置保存，主库与测试库用途和权限分别核对 |
| Git 凭据 | 每项目独立 Deploy Key，仅授权目标私有仓库，固定 SSH 主机指纹 |
| 控制令牌 | 经专用 socket 和受限目录使用，不要求业务人员粘贴 |
| 上传资料 | 只给获准对话或项目使用；其中脚本、宏和指令不自动获准执行 |
| 日志与备份 | 限定读取者和保留期限，反馈前脱敏 |

生成的 `ops/project.env` 和控制状态不可提交到公开仓库。排障时不要输出所有环境变量或含秘密的完整 Compose 解析结果；优先使用 `projectctl.sh <slug> validate`。

## 模型、供应链和发布

上游版本与提交由 [versions.env](../config/versions.env) 记录。源码提交、镜像 tag 和不可变镜像 ID 不能混为一谈。

模型调用可能传输当前任务允许读取的源码与资料。部署者需核对供应商、费用和数据政策。开源代码不提供模型账号、配额或供应商可用性承诺。

测试通过不自动授权生产发布。发布应绑定项目、候选版本、验证和授权；主库迁移、恢复及破坏性清理需明确范围与恢复方案。`projectctl.sh <slug> down` 保留数据卷，但停服务不等于备份，备份成功不等于恢复已验证。

## 反馈安全问题

普通问题可提交 [GitHub Issues](https://github.com/zhiyuxinxi/ForgeAdminHarness-open-source/issues)，附版本、最小复现和脱敏错误。涉及可利用漏洞、凭据或客户数据时，不公开敏感细节；仓库若提供私密漏洞报告入口，优先使用。没有专门入口时，先发不含漏洞细节的联系请求，与维护者建立安全传递方式。当前文档不承诺响应时限。
