## 已知安装条件与未覆盖项

### 必要镜像并非全部公开可下载

[版本配置](../config/versions.env)中存在多个本地 `forge-harness` 镜像引用。基础同步脚本的构建范围不等于所有 Manager、Broker、验证及发布组件都已准备完成。请按[上手指南](getting-started.md)逐一核对实际角色镜像，不能直接执行启动后将缺镜像当作模型问题。

本仓库中的 Dockerfile、升级脚本和历史命名只说明源码存在，不承诺其所有父镜像可以在外部环境获得。

### 应用底座来源需要明确选择

现有初始化流程的默认上游取源与维护者发布的 ForgeAdminFoundation 是不同入口。首次准备项目时应确认实际底座来源和固定版本；不能因为 README 相互链接，就认为初始化脚本已经自动切换到该修改版。联合安装需要另外验证，不能直接用另一仓的地址替换所有上游固定提交而忽略兼容性。

### Git与数据库必须提前准备

项目创建不代替数据库管理员创建共享服务、主库、测试库和权限。项目私有Git及写入身份同样需要按脚本要求准备。不要把公开源码GitHub地址直接当作所有用户业务项目的发布目标，不要把真实密钥放进配置示例或Issue。

### 文档解析和技能存在场景边界

文档提取实现不保证扫描图片、复杂排版和全部Office文件完整解析。技能目录包含试行状态；复杂任务的上下文恢复、流程接入和模型行为仍需按真实场景验证。

### 历史项目不会自动拥有全部新能力

模板、规范和运行镜像需要由操作者按影响范围升级。新源码在仓库中出现，不意味着既有工作舱或应用运行端已经切换。

## 后续公开更新如何理解

后续更新应列明公开版本实际包含的新增、修复、升级要求、已知限制与验证范围。维护仓库会先形成可公开候选，再清理配置、资料与数据，保留本仓库的独立历史及对外文档；不会把私有仓库历史直接作为公开更新。

当前没有公开定时自动同步服务。存在一个修复的内部记录，也不等于该修复已进入你的下载版本；遇到问题请先记录当前公开提交。

## 反馈问题

一般缺陷和使用问题请到 [Issues](https://github.com/zhiyuxinxi/ForgeAdminHarness-open-source/issues)，提供：

1. 公开提交或版本、系统与主要依赖版本。
2. 实际执行的步骤、预期结果、实际结果。
3. 已脱敏的错误摘要；可以说明哪一步成功，哪一步失败。
4. 涉及的组件类型和配置项名称，不提供真实凭据或完整环境备份。

安全问题按[安全说明](security.md)选择可用的私密反馈方式。发布Issue或共享日志前去除客户信息、令牌、Cookie、数据库连接凭据和私钥。
