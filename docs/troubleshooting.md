# 常见问题与最小排查

先记录正在使用的公开提交、操作入口、项目、发生时间及原始错误。一次只定位当前失败阶段；已成立的上游结果不需要因为下游失败而全部重做。

| 现象 | 首先核对 | 后续处理 |
| --- | --- | --- |
| 无法拉取 `forge-harness:...` 镜像 | 该值是否只是维护环境本地标签 | 对照[安装限制](getting-started.md#当前公开版的具体限制)准备对应制品；不要把改成任意可拉镜像当兼容修复 |
| 提示 `Host is not bootstrapped` | 本机配置的运行根目录、交付账号与初始化结果 | 按[上手指南](getting-started.md)准备主机；不要把另一个环境的状态复制过来 |
| 提示 `Baseline is absent` 或镜像校验不符 | 基线锁、实际镜像身份、固定源码输入 | 明确缺少哪个制品或绑定，修复这一层；不删除校验 |
| 数据库连接或迁移失败 | 主库/测试库是否创建、账号授权、初始化版本和网络 | 项目创建不会自动建共享数据库；由管理员修复数据前提，保留失败迁移证据 |
| 项目创建成功但无法启动 | 私有远端是否 attached、文件目录、运行合同、镜像和数据库 | 使用 `projectctl.sh <slug> validate` 的直接错误定位，不以创建成功推断启动条件齐全 |
| 登录后没有目标项目 | 账号是否 active、项目成员列表是否包含该项目 | 管理员核对 `conversation-userctl.sh list`，不共享账号 |
| Gateway 能访问，进入对话失败 | Manager 状态、动态端口、Host/Origin、代理和防火墙 | 核对该项目及该对话访问路径，不只测首页 |
| 模型无法回复或返回鉴权/限流错误 | 当前供应商授权、网络、额度及错误类型 | 修复对应模型连接；不要在聊天中粘贴 API Key |
| `--git-url` 被拒绝或私有 Git 不同步 | 是否使用独立私有 SSH URL、Deploy Key、固定主机指纹和正确分支 | 采用 `project-gitctl.sh` 核对；不关闭 SSH 验证、不强推覆盖远端 |
| 发布候选过旧或发生冲突 | 当前集成提交是否已被其他工作舱推进 | 在自己的工作舱处理实际冲突，保留他人的集成结果 |
| 模型说完成，但页面未变化 | 是代码完成、验证完成还是发布完成；当前运行版本是什么 | 查对应发布任务终态与版本，不用对话措辞代替发布结果 |
| 验证长期等待 | 当前任务、实际执行器与直接日志 | 保留任务标识，由管理员定位队列、执行器或失败阶段；不重复提交同一发布请求 |
| 作业手册引用旧版本或模型样本 | 是否位于带日期的历史说明或 `_meta/` | 以[公开版本](release-status.md)和当前代码为准；旧样本不证明你的环境已验收 |

## 管理员可用的定向观察命令

```bash
sudo bash scripts/conversation-control-planectl.sh status
sudo bash scripts/projectctl.sh demo status
sudo bash scripts/projectctl.sh demo harness-logs
sudo bash scripts/project-gitctl.sh demo status --require-synchronized
```

仅使用和当前问题有关的命令，替换示例项目名。日志可能包含业务内容，分享前脱敏。命令执行失败不应通过放宽全部权限或关闭隔离解决。

## 提交可复现的问题

向 [GitHub Issues](https://github.com/zhiyuxinxi/ForgeAdminHarness-open-source/issues)提供：

1. 公开仓库提交、相关组件版本和系统环境。
2. 正在做的一个动作，以及最短复现步骤。
3. 期望结果、实际结果和脱敏原始错误。
4. 是否为全新安装；失败发生在准备、登录、对话、验证还是发布。
5. 已尝试的直接修复及其结果。

不要提交密码、Key、完整环境文件、客户资料、私有 Git 凭据或未脱敏数据库内容。安全漏洞按照[安全说明](security.md)处理。

## 当前不能由文档补齐的事项

完整公开镜像与构建输入、两公开仓库的固定兼容基线、全新环境安装与真实对话验证，仍需要实际发布和验收工作。文档标明这些边界，不把内部环境成功记录转述成外部使用者已经可以无障碍安装。
