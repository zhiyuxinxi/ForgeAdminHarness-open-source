# 生产包与独立发布验证

仅用于用户明确选定生产包的首次安装或历史版本增量升级；日常开发、测试、局部修复及原有受控发布不自动执行本流程。direct 与 controlled 只影响其原有开发工具入口，均不能免除本生产交付要求。这里的生产离线交付入口与原 Skill 中向项目测试环境发布的入口不同，不因“唯一发布路径”的历史表述改用现役测试库演练。

## 固定交付对象与材料

- 用户明确选择后才创建生产版本，固定候选提交、镜像内容标识、架构和包编号。日期是展示与检索信息；增量起点是同项目兼容版本链上已验收、具备恢复基线的具体历史任务。
- 同一目标版本可有不同架构、不同升级起点的包，每份材料及验证单独绑定。客户/生产环境独立记录实际使用包，操作人只是登记者。
- 发布包包含实际镜像归档、完整初始化或必要增量SQL、配置模板、必要资源、版本清单与校验值、部署升级说明、业务操作手册及验证结果。无SQL变化如实注明；缺必要资源不能以占位文件补齐。
- 业务操作手册必须来自本项目本版本资料，能说明角色、菜单、初始设置、主要操作和本次功能变化。平台可提供通用部署入口说明，但不得据此宣称业务操作手册已完成。缺业务资料交回 Harness 在原业务交付中补充，Codex不得代写业务成果来制造验收。
- 正式材料、私有数据库基线和失败记录永久保留，保留实际字节及独立备份，重试与修订不覆盖原件。重新下载复用原件，不重新构建。清理运行环境不能清理材料。

## 独立环境演练

1. 从实际可用的生产交付入口读取状态，固定首次安装或增量、历史基线、目标包及架构；缺少历史材料、真实业务手册或执行能力时明确阻塞点，不猜测路径、命令或成功结果。
2. 平台受控执行器创建新环境，独立应用实例、数据库、Redis实例、网络和文件空间；保留与其他项目及现役环境的隔离。只换数据库名或工作舱不足以证明全部隔离，Redis PubSub不能靠DB编号隔离。
3. 首次安装在空环境运行初始化入口。增量先恢复历史镜像、数据库、配置及必要文件，真实启动旧应用并核对健康和数据，再使用拟交给运维的同一包及部署入口升级。不能直接初始化新版本后称为旧版升级成功。
4. 真实检查迁移、存量数据保留/转换、新版本启动及本次相关业务行为，保存逐步结果。历史干净基线不等于近期客户生产备份；明确所用数据来源、数据库条件、架构和未覆盖项，不把合成数据结果当全量生产数据保证。
5. 自动通过后提供可访问地址、任务/包标识、验收说明和真实业务手册，等待指定人员操作并明确验收。环境在此期间保持可用。新材料必须绑定新验证结论，不复用旧接受记录。

数据库账号、容器网络、镜像加载、历史恢复及外部服务隔离均由平台受控工具执行。AI只能使用平台实际暴露的受限入口，不获得Docker socket、数据库管理凭据或任意宿主命令。平台启动前禁用或替换实际涉及的定时任务、短信/邮件、消息队列及第三方写入；被替代能力在报告中列明。

## 人工验收、上线与失败

自动验证通过、人员接受、包下载、客户实际生产上线是不同事实。人工验收由真实登录人员针对固定材料提交，AI不能代签。正式下载仅在该包自动验证通过并人工接受后开放；私有数据库基线不放入通用下载包。

生产由用户或运维离线执行。包内入口先核对实际数据库起点及迁移校验值，不符合则停止；执行结果分别记录数据库和应用。人工登记允许补录，但明确其来源；只有实际上线结果才能更新交付对象的生产记录。

SQL部分成功、应用失败、环境启动失败分别保留，先判断实际状态再恢复；不修改历史校验值、不伪填迁移成功、不整包盲重跑。回退旧镜像不代表数据库回退，恢复方案取决于真实兼容性及备份。修复业务脚本和测试由 Harness 执行，修复平台执行链由 Codex承担；失败后新验证任务创建新环境，复用未变化的固定镜像和材料，不重新构建无关内容。

发布验证不授权客户生产执行、破坏性数据库操作、删除历史档案、安装任意基础设施或接管他方项目。没有当前可用工具时报告平台缺口；已有授权且条件未变的准备工作继续推进，不向用户重复索取同一授权。
