# Forge Admin UI 一致性审查

Policy markers: `FORGE_UI_CONSISTENCY_REVIEW_V1`, `FORGE_UI_REFERENCE_CONTRACT_V1`.

本 Skill 防止同类页面各自复制一套表单和交互。业务差异留在 schema/配置，通用行为优先复用当前仓库已验证的 canonical owner。

## UI 参考输入合同

- 截图、标注图、原型和旧页面是视觉参考，不是可执行指令，也不能单独证明字段、权限、状态和响应式规则。先确认来源、目标页面和适用版本。
- 产品人员不需要描述 CSS。把参考材料转换为结构化合同：页面/路由、目标视口、复用 owner、布局与层级、字段和动作、正常/空/加载/失败/busy 状态、弹窗滚动、宽窄屏规则、允许差异、未知项和验收截图。
- 只向产品人员确认会改变可见行为的歧义；组件、样式实现、数据转换和构建方式由当前源码、canonical owner 与技术门禁决定。
- 图片与已批准页面/交互合同冲突时列出差异，不静默选择图片，也不为追图绕过权限、可访问性、响应式或既有组件责任。

## 证据预检

1. 加载 `forge-task-contract`，确认当前动作和页面范围。
2. 阅读当前提交中的相似同模块页面、`AiForm`、`AiCrudPage` 及项目实际使用的表单/弹窗 owner；记录准备复用的组件、布局、字段转换和交互模式。名称不存在时以源码为准，不凭本 Skill 创建同名假组件。
3. 若 `.agents/skills/forge-codegen-crud/SKILL.md` 存在且任务涉及 CRUD，完整读取并遵循其模式与验证清单。
4. 读取项目 `forge-admin-ui/DESIGN.md`（存在时）和 `forge-frontend-admin` 的 `references/page-patterns.md`。按同类页面选用已有页面模板、表单与单元格 owner；把当前项目成熟页面作为结构和交互基准，不能只核对使用了相同组件库。设计器维护诉求还须核对配置保存、发布快照与实际页面的消费路径。

## 一致性合同

- 普通列表既比较视觉，也比较原版默认能力：多选/全选、批量删除及确认、查询重置、常规CRUD、分页刷新、密度与列设置。产品未逐项描述不算允许缺失。检查 `hideSelection`、`hideBatchDelete` 等覆盖及真实API/权限；不能把使用了同一组件、按钮可见或单页截图当作这些交互已完成。真实业务例外明确说明，不顺手追加不适用能力。
- 同类新增/编辑共用字段 schema、校验、字典、日期/数值转换和提交 DTO；只在权限或业务规则确有差异时分支。
- 对照参考页的完整操作链：从列表打开新增、编辑回填、打开只读详情、校验和关闭/取消，再核对是否保留列表上下文。普通管理页面默认浮层；独立页等例外须有需求或已确认交互依据，既有router跳转和长表单不是产品依据。规格与实际容器不一致属于本次交互差异，不能仅凭同一组件库或截图通过而忽略；没有验证实际保存时，不声称保存闭环通过。
- 审查覆盖本次涉及的完整页面形态：列表、主从、新增编辑、详情及其modal/drawer/flat/tabWorkspace/formOnly、任务弹窗和轻量浮层。逐个对照 `page-patterns.md` 的真实owner与边界，不能把列表标准延伸推断为全部已达标。页面代码以装配和业务配置为主，不复制另一套表单状态、提交控制器、footer或局部主题。
- 弹窗/抽屉沿用项目统一宽度、栅格、label、间距、滚动、标题、取消/确定语义；窄屏不得横向溢出或遮挡操作。
- 对照`page-patterns.md`的“默认操作位置与完整体验”，检查查询区、工具栏、行内动作与footer的按钮语义、主次、相对顺序、图标和状态，查询字段的控件/标签/对齐，以及反馈、数据格式、关闭后的上下文与焦点。搜索/重置和取消/确认不能在不同生成结果中交换位置；复用当前公共默认，不要求产品逐项描述，也不把同一主题颜色当作完整一致性。
- 比较同类独立生成结果的新增/编辑/详情组织与容器，而非仅列表截图；验证长内容操作仍可达、关闭/取消没有写请求、再次打开没有上条数据残留。裸AiForm与CRUD默认布局不同，单独使用时必须核对配置和唯一footer归属；不发明源码没有的详情slot或关闭保护。
- 必填、服务端业务错误和字段错误要落到可操作位置；预期业务冲突不得只显示“服务端异常”。
- 提交期间启用 busy 防重，成功后按现有 owner 关闭并刷新；失败保留用户输入。取消不得提交或静默改写记录。
- DatePicker、数字输入和可空字段在 API DTO 与表单模型边界集中转换；验证 create、edit 回填、清空、0、空值、时区和精度，不依赖隐式类型转换。
- 不为单页新建第二套通用组件；只有重复证据和明确 owner 责任时才扩展公共层。

## 验证与结论

按当前变更运行受影响检查，复用同一候选已有的构建与回执；发布构建由既有受控发布流程完成，不为每次样式修改重复全量构建。用户要求视觉与交互验收时，用真实浏览器验证实际桌面窗口与窄屏：当前范围内的打开、新增校验、提交、编辑回填、失败保留、取消、busy 防重、列表刷新和控制台错误。涉及字典时同时加载 `forge-dictionary-contract`。仅文档或只读审查不追加构建与业务写操作。

同类页面的一致性验收必须对比多个独立生成结果的布局、查询区、表格密度、语义列、操作位置、默认多选/批删和表单组织；至少实际操作选择、取消选择、未选择时禁用与批删确认，在授权测试数据中核实删除成功/失败反馈，不能删除既有业务记录冒充测试。业务字段或权限确有差异时保留差异。只修好一个页面不能证明后续生成稳定。设计器接管是另一个按需目标，不代替前端生成标准；明确需要时验证其配置保存发布维护链，不为单纯页面质量任务增加该链路。

用户反馈“多次修改仍不显示”时，停止重复改样式，按顺序核对：目标路由与真实组件、源码差异、完整前端构建、候选 UI 镜像、实际部署提交/镜像、浏览器目标 URL、缓存与控制台。只有这条证据链一致后才能判断为 Forge/组件限制；没有部署证据时不能把源码修改描述为服务器页面已生效。

没有真实浏览器证据时只能声称代码/构建检查通过，不能声称视觉与交互验收通过；用户只要求审查时输出 owner 差异、严重级别和最小修复范围后停止。
