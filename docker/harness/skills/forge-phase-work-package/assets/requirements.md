# Requirements 阶段交互卡

## 本阶段需要的业务资料

- 业务目标、使用角色、真实场景、成功标准和明确非目标。
- 现有产品说明、页面或接口资料的稳定版本/来源；不要上传凭据或生产数据。
- 必须由业务 owner 决定的规则，尤其数据归属、租户边界和权限矩阵。

## 本阶段关注点（提示由 Controller 自动生成）

只梳理本次要解决的业务问题：角色、用例、业务规则、验收条件、非目标、数据归属和权限矩阵；资料不足时明确尚待决定的具体业务问题，不设计库表、不写代码、不进入后续阶段。同事只需提供实际业务资料和回答业务问题，不需要复制 phase ID、字段清单或机器参数来拼 prompt。

## 阶段输出与停止条件

- 输出八类需求合同字段和需求到验收的编号映射。
- 面向同事先自然说明本阶段已经明确哪些用例和规则、它们对交付的影响；若资料不足，只提出会改变业务结果的待决问题并给出建议。唯一机器 artifact 块及全部 payload 字段仍须保留在技术区。
- 任一关键业务决定未解决，立即暂停并交回 owner；不得用常见做法代替决定。
- Controller 封存工作包后才能交给 domain-contract。
