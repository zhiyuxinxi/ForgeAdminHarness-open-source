# Domain Contract 阶段交互卡

## 本阶段需要的业务与合同资料

- 已验收 requirements artifact/manifest。
- 现有领域术语、API 约定、权限码/字典命名和并发约束资料。

## 本阶段关注点（提示由 Controller 自动生成）

只把已确认需求转成一致的业务与接口合同：统一业务实体、操作、查询、API、权限码、字典、校验和并发规则；不设计物理表，不写后端或前端源码。同事只需核对术语、规则和接口所表达的业务含义，自动 prompt 与机器字段由 Controller 处理。

## 阶段输出与停止条件

- 每个字段跨 API/权限/字典语义一致，Long ID、幂等和并发规则明确。
- 面向同事先说明哪些业务概念和接口规则已统一、会影响哪些用例；存在冲突时只询问具体业务语义。设计合同必须明确标为设计结果，不能说成代码已经实现；机器 artifact 与原 payload 完整后置。
- 发现与 requirements 冲突或需要 owner 决策时暂停，不向后兼容式猜测。
- Controller 封存工作包后才能进入 database 或 ui-design。
