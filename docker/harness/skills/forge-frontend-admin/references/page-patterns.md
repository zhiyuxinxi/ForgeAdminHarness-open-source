# 管理端页面模式与默认交互

新增或改版管理端页面、表单、弹窗、抽屉和浮层时读取。本参考统一整套前端的代码骨架、共有呈现和默认行为，不把专用地图、图表或设计器强塞进 CRUD。字段、流程、权限和真实筛选差异必须保留；用户指定的效果及当前项目合同优先。产品无需逐项描述基础交互，也无需指定CSS或组件调用方式。

## 既有模块的标准化修复

任务要求调整既有模块时，完整默认规范同样适用，不能降为换色、格式化或修一页示例；范围仍限用户指定模块，不自动扩展全站。

- 结合实际菜单、已注册路由和已有页面确定本模块的可达入口，包括直接链接、新增编辑、详情及审批入口；页面文件存在不等于菜单可达。入口、返回或刷新出现404属于本模块的直接缺口，须与相关页面一起修复，不能隐藏入口或要求用户手输地址绕过。
- 按实际页面类型和共享业务组件分批调整，再复用下文对应公共owner；普通台账、主从、地图、流程及设计器保留各自业务结构。已达标部分和有效证据直接复用，正常合并其他会话成果，不为形式重写或覆盖已有人工配置。
- 同一批同时落实查询与按钮、表格、表单、可读详情、弹层及完整操作过程；新增编辑回填、成功刷新、失败保留与重试、关闭返回上下文均按下文默认规则处理。列表外观通过不能代替这些流程，检查仅覆盖本批修改和明确直接影响。
- 普通台账沿“普通列表的默认交付”提供选择与真实批删，普通新增编辑沿“表单、详情与覆盖层的默认交付”使用modal。只读归档、审批状态、库存流水等例外须有真实业务或权限依据；旧代码缺功能、已有独立路由、字段多均不是例外依据。
- 区分缺口归属：平台执行问题及低代码/通用组件能力缺口提供直接证据和所需接口，交操作员修复公共底座；业务配置、业务代码、业务测试及受控发布仍由原Harness对话完成。不要在业务页复制公共逻辑绕过缺口，也不要让已定位的局部阻塞阻止其他可推进页面。

## 先找到实际 owner

以下路径均相对当前业务仓库，不是 Harness 仓库。先看 `forge-admin-ui/DESIGN.md` 和原版 `forge-admin-ui/src/views/system/user.vue` 的相关区块，再核对将使用的 owner；缺文件时在当前项目查找同职责实现，不复制另一客户代码，不假定历史接口仍存在。

- 页面及表单：`forge-admin-ui/src/components/ai-form/AiCrudPage.vue`、`AiCrudPageProps.js`、`AiForm.vue`。
- 查询及表格：同目录 `AiSearch.vue`、`AiTable.vue`。
- 主从布局及语义单元格：`forge-admin-ui/src/components/common/MasterDetailWorkspace.vue`、`SystemTableCell.vue`。
- 非CRUD任务弹窗：`forge-admin-ui/src/components/ai-modal/index.vue`；字段内容仍复用 `AiForm`，先读真实 `open`/`onOk`/`onCancel` 回调和异步行为。

复用源码能力，不复制整页 CSS 或用户管理业务。确认实际 prop、slot、事件与数据格式后才调用；例如配置列采用 `prop`/`label`，不是把原生表格列直接传入。相同页面类型沿用这些 owner 的默认布局、密度和交互，不因另一次生成重新选择一套样式。

## 页面与容器模式

| 模式 | 共享结构 | 业务只补什么 |
| --- | --- | --- |
| 普通台账 | `AiCrudPage` 内部的 `AiSearch`、工具栏、`AiTable`、分页和表单 | `searchSchema`、`columns`、`editSchema`、`apiConfig`、权限及必要 hooks |
| 主从工作区 | `MasterDetailWorkspace` 的 `aside` 与默认插槽；右侧复用台账或详情 | 树/分类的真实选择状态、筛选参数与对象级操作；无主从关系不添加左树 |
| 新增/编辑弹窗及分组表单 | `AiCrudPage` 默认modal，创建和编辑共用 `editSchema` 与提交链 | 字段规则、业务分组、初值/回填、联动、只读字段和必要子表 |
| 新增/编辑抽屉 | 同一 `AiCrudPage`，`formOpenMode: 'drawer'`；旧入口为 `modalType: 'drawer'` | 仅容器切换，继续使用同一schema、校验、API、权限与提交链，不再写一套 `NDrawer + NForm` |
| 同页长表单/多页签编辑 | `formOpenMode: 'flat'` 或 `'tabWorkspace'` | 业务字段和必要子表；继承现有页签、记录复用、滚动正文、动作区与关闭语义，不手写第二套工作区 |
| 独立新增填报 | `AiCrudPage formOnly` | 新增字段、接口与成功后的业务行为；`formOnly`不是通用新增/编辑/详情路由开关 |
| 详情/审批 | 同一表单owner的只读详情、`detailPanels`、`detailActions`等真实接入点 | 完整详情字段、真实流程与状态允许动作；不把审批当普通编辑保存。当前详情使用独立详情modal，不假设编辑drawer会自动让详情也进drawer |
| 非CRUD任务弹窗 | 已有 `ai-modal` 外壳加同一表单owner | 任务字段、实际校验、异步确认回调及业务结果；不另写标题、footer、关闭、loading和错误壳 |
| 轻量浮层 | 关联值使用 `SystemTableCell :values`；操作菜单/确认复用同模块现有Naive owner | 简短说明、关联值或少量动作；复杂录入使用表单容器，不塞入Popover。只读关联值浮层不承担编辑或删除逻辑 |

普通台账不得在页面再手写一套搜索、表格、分页、表单弹窗或页面外框 CSS。现有 `toolbar-start`、`toolbar-end`、列 `render` 等扩展口可放业务内容；先核对接口，不假设有某个 slot。专用交互不足时只补必要扩展，不为它替换整个共享工作面。

## 标准代码组织

沿当前相邻模块的Vue SFC、导入顺序、命名和lint格式。页面负责装配公共owner，字段/列/schema/API配置保持声明式；同一对象的新增、编辑、详情共用字段定义，差异通过实际权限、状态和hooks表达。复杂配置可放同模块已有配置文件，简单页面不为形式拆出空壳模块。API调用进入实际使用的 `src/api` 与既有HTTP层，数据转换在明确边界集中完成，禁止复制鉴权、响应解析和错误拦截。

可直接复用 `src/components/page-templates/SimpleCrudTemplate.vue` 的 `crudProps` 或 `AiCrudPage`；需要slots时直接使用支持该slot的真实owner。代码标准不是每页生成一套名为“标准”的本地组件。普通页面不新建重复的form state、modal state、submit/reset/delete控制器及局部主题；专用流程只添加业务动作所需状态。

## 表单、详情与覆盖层的默认交付

普通管理端新增/编辑默认使用既有modal，详情沿用同一页面的公共详情浮层，关闭后保留列表上下文。采用drawer、同页工作区或独立路由，须有当前需求或已确认同类交互依据；现有代码已经跳路由、字段多、表单长、具有草稿/提交两种业务动作，都不能单独构成独立页依据。需求明确使用弹窗时，不能改成独立页；无法取得原始需求时，如实说明来源边界，不能把AI编写的规格或已有实现冒充产品确认。同类页面固定沿用有依据的容器模式。

适合分组的常规业务表单参照原版用户管理 `editGridCols: 2`、`modalWidth: '900px'`；简单表单保留公共一列默认。不要为“好看”把全部表单硬改两列，或每次生成自行选择800/900/960等宽度。同类详情沿公共 `detailModalWidth` 默认，只有明确内容需求才覆盖。字段长文本/分组标题按实际 `span` 跨列，窄屏交由公共容器收敛。

- **新增/编辑共用协议**：初值、校验规则、字典、日期/数值/空值转换、提交DTO共用；打开编辑先按实际detail接口回填，不把列表行缺失的字段作为空值提交。再次打开必须清除上一记录的残留状态。
- **只有一套表单与footer**：CRUD内部已经管理 `AiForm` 和操作区，不在外面再套表单、额外保存按钮或自行调用第二次提交。专用任务直接使用 `AiForm` 时，显式与所选模式的列数、label、gap和footer归属对齐；裸 `AiForm` 与CRUD的默认gap/footer不同，不能混搭后假定一致。
- **提交和取消行为**：字段错误定位到实际控件；异步提交期间显示busy并阻止重复提交；失败保留输入并可重试；成功沿owner关闭/保留工作页并刷新相关数据。取消与关闭不得触发写请求；不要为整齐而忽略未保存内容的现有保护。普通modal/drawer、同页工作区的关闭语义以当前源码为准，不能凭文档宣称所有容器已有脏数据确认。
- **覆盖层结构**：标题、关闭入口、正文与右侧操作区由公共owner提供。长内容应滚动正文、保持操作可达，宽窄屏不能横向溢出；缺口修在实际公共owner，禁止每页复制 `max-height`、固定footer或全局深层样式覆盖。简单浮层保持轻量，长关联值列表也要可滚动。
- **只读详情**：默认使用公共 `detailPanels` 的 `descriptions` 面板展示完整字段和合理分组，并设置 `hideDefaultDetailContent: true`。保留标签、字典和值格式；操作与审批只出现在真实权限/状态允许的位置。禁止将禁用编辑表单或“从列表前12列生成禁用input”的兜底当正式详情，也不发明 `#detail` 或 `detailRender` 等未经源码确认的入口。
- **详情附件**：`descriptions.fields` 中的附件显式配置 `field.render.type: 'fileUpload'`，保留原字段值并复用公共只读附件列表及已有权限下载；隐藏默认表单后不能通过过滤附件类型丢失内容。先核当前项目的 `ExpandDescriptionsPanel` 已具备此能力，未交付时交公共底座补齐，不在业务页伪造文件链接。
- **详情可读值**：字典字段沿 `dictTag` 展示标签；关联 `select` 使用真实详情名称或已有选项的名称映射，不直接显示 code/ID，也不编造未加载的名称。
- **异步详情归属**：详情与编辑加载绑定当前记录和本次打开请求；切换后清除旧内容，忽略迟到响应，不能将旧字段配到新 ID。读取失败须显式提示并提供真实重试，公共加载缺口修在所属组件，不每页复制控制器。

上述默认同样适用于独立示例与生成器产物。交付前按本次真实使用的容器核对打开、编辑回填、必填校验、取消、busy、成功反馈、失败保留及重复打开；只验证列表不能证明其新增编辑和弹层已标准化。

## 普通列表的默认交付

产品只描述业务对象、字段和业务规则时，下面这些常规能力仍默认交付，不要求产品逐项补写。原版用户管理及同一个 `AiCrudPage` 是行为基准，不能只模仿颜色和间距。

| 默认能力 | 生成代码应做什么 |
| --- | --- |
| 多选与批量删除 | 保留左侧多选列、全选及批量删除入口；未选择时禁用，删除前按选中记录确认。`hideSelection`、`hideBatchDelete` 的公共默认均为 `false`，普通台账不主动覆盖为 `true`。 |
| 常规操作 | 保留查询、重置、新增、详情、编辑、单条删除和公共工具栏；绑定真实 API、权限、忙碌态、成功刷新和失败反馈。 |
| 表格工具 | 保留分页、刷新、密度和列设置；普通表格沿用 `medium` 与统一布局，不每次重选边框、条纹、行高或按钮样式。 |
| 导入导出 | 是否提供由实际需求或既有项目合同决定，不因页面属于 CRUD 就默认添加。需要时复用真实接口，落实权限及进度、结果和部分失败反馈；不能显示无接线按钮，也不能漏掉已明确要求的能力。 |
| 常见状态 | 沿公共组件处理加载、空数据、无匹配、失败、无权限、确认、取消及重复提交；字典和值格式保持原版语义。 |

先读取 `AiCrudPage.vue` 的真实删除实现和 `apiConfig.delete`，再选择项目既有批量端点或组件支持的 `/:id` 逐条调用。只有单条删除接口不构成隐藏批量删除的理由；ID 始终为 string。批量操作继续遵守后端权限、租户和记录状态，部分失败必须保留真实失败结果，不能在前端假报全成功。

存在审批中不可删等业务限制时，在既有动作权限和状态规则中表达；不能把某些记录不可删除扩大成整个页面默认无多选、无批量操作。只读查询、审计记录等确实不提供删除的页面，必须依据明确业务语义或真实权限/状态限制保留例外，并在交付说明中说明。缺删除 API 不等于已证业务禁删，应按前后端分工补齐真实能力，再接公共批删；已有单删可复用上文逐条调用。独立生成的示例同样遵守默认值，不能用 `hideBatchDelete: true` 绕开真实接线。

这组默认属于前端代码生成质量，不以接入低代码设计器为前提。只有用户另有可视化维护要求时，才继续本参考后面的设计器协议工作。

分组表单的真实基础接口是 `editSchema`、`editGridCols`、`modalWidth`；原版用户页用 `type: 'divider'`、`label`、`span` 分组，字段使用 `field`、`type` 和顶层 `rules`。不要发明 `formGroups`。两列业务表单可沿用原版的两列及约 900px 容器，简单表单沿用现有默认；窄屏跟随公共容器，不在每页重算尺寸。

详情与编辑共用字段含义，但使用各自适合阅读或录入的配置。常规详情通过 `detailPanels` 配置分组：每组使用 `type: 'descriptions'`、`dataSource: { type: 'row' }` 和 `descriptions: { columns: 2, fields: [...] }`；字段使用真实的 `field`、`label`，长文本按需跨列，字典字段沿已有 `render: { type: 'dictTag', dictType: '实际字典类型' }` 展示可读值，并设置 `hideDefaultDetailContent: true` 去掉默认编辑表单。简单详情可使用一列。必须读取当前 `ExpandDescriptionsPanel` 与字段渲染实现确认支持的格式，不能臆造属性、直接显示关系 ID 或残留必填星号。`detailActions`、`runtimeActions` 的动作、流程和权限结构继续沿当前实现；专用详情仍复用容器、加载、关闭、失败恢复与重复打开行为。

## 同类页面保持一致的部分

- **边界与密度**：沿用应用 Layout 外边距，避免重复面包屑、大标题、外层白卡和多层 padding。`/system/**` 的自动 `SystemPageLayout` 不代表所有业务路由也已包裹；先查实际路由边界。Flex/Grid 内容区保持 `min-height: 0` 和明确滚动区域，分页不能被无意义顶部留白挤出工作区。
- **查询与操作**：查询项有可理解的 label 和 placeholder，常用项先显示，其余走公共折叠；不在页面堆固定宽度输入框。每个区域一个主动作，批量操作反映实际选中项。真实统计或状态筛选保留，但可用紧凑导航表达，不为装饰生成大指标卡。
- **表格语义**：名称是主信息，编号/账号是换行辅助信息；使用 `SystemTableCell` 的 `title`/`subtitle`，关联集合用 `values`。`interactive` 必须接真实 `activate` 行为。状态用 `DictTag` 或语义 Tag，普通属性保留文字；常用行操作最多两个，其余走既有“更多”。默认密度沿用 owner 的 `medium`，不自行改每页行高。
- **主题与表单**：颜色、字重、间距、圆角和控件尺寸来自当前主题与公共组件。分组、必填、校验、只读、按钮位置及弹窗关闭行为使用同一规则；不添加局部主题、硬编码颜色或第二套 UI 库。
- **真实状态**：区分加载、无数据、无匹配、失败和权限不足；只渲染有内容的提示。缺失标题/级别先核数据与映射，不编造值；逾期时长按真实截止时间表达“已超时”，不能显示难懂负数或为美化清零。保留安全水印与业务权限。

原版质量来自字段优先级、操作归属、紧凑布局和完整状态共同成立；仅使用同一组件库、增加颜色或压缩间距不算达到要求。

## 默认操作位置与完整体验

这些规则与列表、表单和覆盖层共同适用，不是产品提到某个控件后才补做。读取当前公共实现确认真实接口；共有行为由组件承担，业务页面不复制第二套控制器或CSS。同类页面遵循同一模式，主从、审批、分组表单等仍保留各自的业务结构。

| 区域 | 默认安排 |
| --- | --- |
| 查询操作 | `AiSearch`已经按搜索、重置排列，搜索为primary、重置为secondary，复用图标、size、间距和loading/disabled；折叠及扩展操作沿既有表单入口，不在页面另造一排按钮。 |
| 列表工具栏 | 复用`AiCrudPage/AiTable`已有新增、批量动作、适用的其他业务操作及表格设置位置；动作语义、主次、相对顺序在同类页面保持一致。不要为单页换色、交换位置或额外添加一组重复入口。 |
| 行内操作 | 常用动作保持稳定顺序，低频动作进入现有更多菜单；业务状态可改变合法动作集合，但不能随机改变相同动作的样式和相对顺序。删除使用危险操作语义和确认。 |
| 表单底部 | 复用公共footer，取消在左、确定/保存/提交主动作在右；存在保存草稿等业务次动作时采用固定次序，不能复制另一套提交链。独立重置表单与关闭弹窗含义不同，不互相替换。 |
| 查询与字段 | 标签、占位文案、宽度策略、列对齐、间距、基础/高级查询由现有表单配置承担；根据字段语义选日期、数字、字典或关联选择器，不把所有字段退化成input或用硬编码宽度拼查询栏。 |

- **完整状态**：加载、空数据、无匹配、请求失败、权限不足、只读、禁用及批量部分失败分别呈现。反馈文案指向用户可执行的下一步，失败保留输入，不把错误变成空列表或直接展示后端堆栈。查询/重置遵循公共页码联动，不能让旧响应覆盖新的查询结果；缺口应修实际公共归属，不在每页复制一套请求管理器。
- **可见重试入口**：先核组件真实 slots；当前 `NAlert` 的重试按钮放入实际支持的默认内容，不使用不存在的 `#action`。测试替身不得虚构该 slot；按钮必须真实渲染并调用对应重试操作。
- **上下文与焦点**：关闭新增/编辑/详情后保留合理的列表筛选、页码与位置；重复打开不能残留上条数据。沿公共组件的键盘、焦点、字段错误定位、弹层关闭与未保存处理，缺能力如实说明并修本次直接缺口，不能凭规则宣称已有实现。普通浏览器最大化与常见窄窗口均保持操作可达，不用F11或人为固定视口掩盖溢出/白边。
- **值与文案**：沿公共格式显示空值与0、日期时间、字典/状态、数字、单位和附件，字段/按钮/错误采用一致业务词语。单位、精度、时区、敏感范围和业务规则取实际合同，不由AI编造；保留项目既有国际化差异。业务界面不展示模型、生成过程或实现配置说明。
- **有业务前提的扩展**：附件、导入导出、关联选择、子表等按需求或既有项目合同提供，采用现成控件及进度/结果/部分失败反馈；可见上传必须完成真实上传并取得接口认可的文件标识，不得仅添加本地假文件或弹出成功 toast。API参数、分页响应、空值和DTO转换在既有接口边界统一处理，不在页面创造另一套协议，不为统一样式添加不适用功能。

一致性检查同时看结构、视觉、操作顺序和真实状态；不能只看截图、同组件名或列表能打开。仅验证本次实际涉及的流程和窗口，不要求全站历史页面迁移、全量检查或新增治理机制。

## 让设计器维护真实配置

`AiCrudPage` 是渲染组件，不会把任意 Vue 反编译为设计模型。要求后续用设计器维护时，应让页面消费设计器拥有的模型/页面/表单配置，业务扩展通过当前项目支持的扩展协议接入，不能只写一份看起来相似的 Vue。

按需核对当前项目的这些实际入口：

- `forge-admin-ui/src/components/lowcode-runtime/LowcodeRuntimePage.vue` 接收 `runtimeConfig`，交给 `src/views/ai/crud-page.vue` 转换后渲染共享页面。
- `forge-admin-ui/src/views/ai/crud-page.vue` 消费 `modelSchema`、`columnsSchema`、`searchSchema`、`options`；表单取当前 form profile 的 `editSchema`/`editFormLayout`，子表来自 `options.masterDetailConfig.children`。`editGridCols`、`modalWidth`、`formOpenMode` 等由运行适配器映射，不能把组件 props 不加区分地当作设计器保存协议。
- 后端 `forge-server/forge-framework/forge-plugin-parent/forge-plugin-generator/src/main/java/com/mdframe/forge/plugin/generator/service/businessapp/BusinessObjectDesignerService.java` 保存设计模型及页面/表单草稿，编译运行配置并关联 `modelId`、`modelCode`、`configKey`。
- 同目录 `BusinessApplicationRuntimeService.java` 从应用 `lastPublishVersion` 对应的已发布快照提供正式运行内容，返回 `versionNo`。草稿保存成功不等于正式页面生效。

可维护边界由当前设计器支持能力决定：字段显示、顺序、分组、查询、列、校验或布局配置须存于其真实支持的模型/配置；复杂服务逻辑、特殊渲染或未支持的字段资产属于代码扩展。不要声称所有代码均可拖拽修改，也不要把本该配置的普通表单全部写成扩展。再次生成时保留设计器已有修改和代码扩展归属，不能用新生成整页覆盖。

生成模型或以迁移初始化页面配置时，先读取当前 `LowcodeSchemaValidator`、设计器编译与运行适配器的实际合同。模型 `appType` 表示数据结构类型，不能把管理端终端名称当成该枚举；字段、子表字段及模型引用中的数组必须在最终 JSON 中仍是数组，不能是二次编码的 JSON 字符串。SQL 中拼装 JSON 后检查实际存储类型；顶层配置与 `options` 不得放置互相冲突的同义值。对本次生成的模型/页面运行已有对应校验器或编译器，并核对实际渲染入口；SQL 字符串包含断言、Java 编译或迁移执行成功均不能单独证明设计器能够接管。已经执行的迁移保持不变，修复使用向前迁移，并只更新本次涉及的配置路径，保留设计器已有修改。

主子表必须先核对当前运行适配器与后端关系解析器共同使用的子表键；页面配置、提交 `children`、持久化关系及详情回填使用同一约定，不能仅凭表名、别名或组件名称猜测。以本次生成的实际请求完成“新增主表及明细→重新打开→修改明细→保存并重开”，核对明细数量和字段原值；主表成功或 HTTP 200 不能证明明细已保存，未识别的子表键不得作为成功接受。

初始化已发布配置时，沿当前公共发布协议建立对应版本快照、发布指针及对象关联，不能只写 `PUBLISHED` 和版本号而缺少该版本记录。先核真实发布服务对既有快照的依赖，保持已发布版本不可变；缺失或不一致使用受控修复，不跳过版本、权限或任务绑定校验。

业务对象、运行配置和可编辑页面资产不是同一层。要求设计器维护时，核对当前应用的页面资产、对象绑定、设计入口及发布配置是否完整；菜单能打开动态 CRUD、对象能改字段，不代表列表和表单布局已有可用维护入口。按当前真实应用页面协议初始化必要资产，复用同一对象及配置，不能再造第二份页面或猜测旧路由；应用显示零页面时先查资产和绑定，只有实际接口或路由证据才能判断权限缺口。维护显示项时区分字段默认值与页面级显式覆盖，修改实际生效的层级，并核对其他字段顺序、显示标签、布局和权限保持；只保存成功或默认值已改变不能代替运行效果。

任务要求设计器维护时，完成证据至少包含：从真实设计入口打开该对象，修改一个已声明可配置的显示项，保存并按实际流程发布，重新打开运行页看到该修改，同时原业务操作仍可用。记录对象/配置标识、实际发布版本及验证项；仅有配置文件、保存接口成功或 Vue 中使用共享组件均不能代替这次往返。后续 AI 修改读取当前已保存的设计内容，只调整任务指定路径，并核对原设计器修改仍保留。新增持久化字段、业务规则或权限变更仍按实际开发合同处理，显示配置编辑不自动授权改库。

## 只验证当前交付

公共提交的数据与结果约定：日期由 `AiFormItem` 的字段类型及 `valueFormat` 输出格式化值，普通数字、标识、嵌套对象及子表数据保留原值；页面和 API adapter 不得按数字位数推断时间戳。复用 `AiCrudPage` 的保存链路，鉴权失败（包括请求层正常返回的 `silentAuthError`）不得关闭编辑器、清理草稿或触发成功反馈。自定义提交 hook 保持同一结果约定，不复制一套提交实现。

公共异步归属约定：列表只有当前查询能更新数据、总数、loading和结果事件；详情只有当前记录/打开请求能回填，失败或缺主键不得打开或提交残留记录。保存busy从异步校验及提交hook之前开始，取消或失败后允许正常重试。复用公共入口，不在生成页面重复实现请求控制器；检查过期响应时同样覆盖异步渲染/运行态增强后的写入。

子表工具栏命令沿现有`relationKey`与`actionConfig.inputSchema`或`formSchema/defaultValues`声明输入，公共入口复用AiForm校验、权限、失败保留和幂等尝试。需要从另一子表选择目标记录时使用`actionConfig.recordSelector`的`relationKey`和真实`labelField`，可配置label/placeholder/emptyMessage；先核实际基础版本已消费这一接口。不得在AiCrudPage中追加具体业务动作码/库存字段/客户名称，也不得为新业务扩展旧配置兼容映射。纯配置、公共框架源码和真实运行消费分别验证。

同类一致性要求下，用相同角色、主题和正常浏览器视口对照用户指定的原版及本次同类型样本，比较查询、工具栏、表格、分页、表单和状态；不同业务字段无需逐像素相同。执行当前变更所需的检查及业务操作，不追加全仓审计或未知页面全量回归。视觉、真实功能、设计器往返和镜像实际消费是不同证据，分别报告已验证、失败或未验证。
