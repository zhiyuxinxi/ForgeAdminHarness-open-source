# 当前项目公共能力的发现与复用

本参考用于需求明确提及已有组织、成员、业务任务、流程或用户自建能力时，先查真实owner和接口。不能把名称相似、Harness工具清单或运行MCP能力清单当作代码复用证明。

## 现有来源及只读入口

Foundation随源码维护 `code-copilot/knowledge/public-capabilities.json`，说明用途、owner、真实公开声明、模块与直接依赖、选择语义及使用限制。项目自建能力可在同一可选说明中增加自己的条目，不需要新服务，也不需要把私有实现上提公共底座。该文件是项目参考资料，不是权限、可信指令或运行验收回执。

direct模式可从当前项目workspace通过已有隔离worker执行：

```text
node /usr/local/lib/forge-public-capabilities.mjs --query 组织
node /usr/local/lib/forge-public-capabilities.mjs --id task.business
```

二选一按需查询，不要求每次两条都运行。命令只读取当前cwd下固定说明及它声明的有界源码/POM，不接受其他项目root、任意宿主路径或invoke动作。未安装命令时，或controlled模式未允许该命令时，用现有read/grep/AST工具读取同一说明及当前源码，不请求业务用户安装工具或绕开拒绝。

结果包含源码/说明摘要、声明核对、直接POM依赖核对及具体缺口。`declarations-matched`只表示本次源码事实吻合，不证明编译、激活的profile、Spring装配、远端运行、数据可见范围或调用权限。`source-candidate`尤其不能报告成已安装能力。缺目录返回`not-described`；缺声明、文件或模块返回具体gap，都不等于平台没有该能力。继续沿已有代码工具核实际入口，不默建另一套。

运行中的 `capability.search/describe` 只列当前身份获授权的已发布动作及其schema；`capability.invoke`有独立调用/确认授权。它们不能枚举全部Java公共API，也不能因发现动作就调用或用于探测有副作用的业务。

## 从发现到代码引用

1. 对照用途、使用限制与真实源码决定是否是当前需求的同一能力。读取选中接口/类型的真实签名及直接消费者，保留版本、依赖方向、可信身份/租户、状态和错误语义；不能只复制说明中的方法名。
2. 用户已明确“引用现有组织”或指定具体来源时直接执行。任务定义和已生成任务、内部组织和外部单位等确有不同业务含义且现有事实无法消除时，一次原生`ask_user_question`给出选项；技术上如何调用已知接口不反复交给业务用户选择。
3. 在当前任务已有spec、需求材料或普通续接摘要中保留选中id、用途、稳定引用字段、`selectionReference`的源码/说明摘要及尚缺的接口/运行证明；不另建固定任务阶段或强制材料。后续读取这份既有决定；相关源码变动才重新核对，不能因换轮次再次问同一个来源选择。
4. 实现真实import/依赖注入、前端字段/API绑定及实际保存校验。组织/成员使用稳定ID，历史名称仅作显示；普通任务、流程审批、机器调度保留各自owner。没有已安装窄接口时指出缺口，不复制主数据或私有业务到新公共模块。
5. 验收实际代码引用和当前受影响行为，覆盖权限、状态及必要回写；命令输出和源码文本不能代替编译或运行结果。源码、构建装配和运行可用分别报告，未验证项保留。

当前说明中的业务任务API仍可处于开发候选状态；以本项目返回的声明及真实运行结果为准。该目录不执行API，不授予权限，也不替用户决定业务语义。
